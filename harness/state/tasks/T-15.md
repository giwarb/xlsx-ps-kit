1. **[blocking] 冒頭表の `Invoke-XlsSession { ... }` が有効な呼び出しにならない** → 対応した。
   `skill/SKILL.md` 冒頭表を `Invoke-XlsSession -Path file.xlsx -ScriptBlock { param($app,$wb) ... }`
   に修正(レビューの修正案どおり)。`XlsAgent.psm1:357-366` の `-Path`/`-ScriptBlock` がともに
   `Mandatory` であることと再照合した。
2. **[blocking] `refused` が通常結果と同じ JSON 形状に読める** → 対応した。Recalculate 章を
   「`success`/`errors_found`(status/total_formulas/total_errors/error_summary)」と
   「`refused`(status/reason/links のみ、totals を含まない)」の 2 形状を明示的に分けて書き直した
   (レビューの修正案の構成を採用)。`-Force` の段落も「`refused` ではなく `errors_found`(通常形状)に
   なる」という対比を明記し、`XlsAgent.psm1:3199-3203`(refused)と `3262-3267`(通常)の実装と
   再照合した。
3. **[blocking] CSV の型変換説明が実装と逆** → 対応した。「CSV は全値を文字列化する」という誤った
   記述を、`ConvertFrom-XlsCsvFieldValue`(`XlsAgent.psm1:2680-2730` 付近)の実際の型推論
   (空文字列→`$null`、厳密な `True`/`False`→bool、不変カルチャの数値→`[double]`、
   `Get-XlsRange` が出す形式と完全一致する ISO 日付→シリアル値、それ以外は文字列)に基づいて
   書き直した。実際の制約は「元の型メタデータを保持しないため、数値に見える文字列
   (`"42"` のような部品番号・郵便番号)が数値として復元されうる」ことだとレビューの修正案どおりに表現した。
4. **[should-fix] 採用 #1(Value2/Value/Text)・#5(結合セル)・#9(保護シート)・#8 のスペース入り
   シート名部分が design doc のみを出典としていて実測記録がない** → 対応した(実測して出典を追加)。
   `Invoke-XlsSession` の ScriptBlock 内でスクラッチ用スクリプトを 2 本(`T15-verify.ps1`・
   `T15-verify2.ps1`。フォアグラウンド実行、`Invoke-XlsSession -Path <存在しないパス>` で新規ブックを
   開き保存せず終了)実行し、以下を実機確認した(実行前後で `Get-Process EXCEL` の件数が 0→0 で
   あることを確認済み。孤児なし):
   - `$cell.Value`(括弧なし)は PowerShell では `PSParameterizedProperty` の記述子オブジェクトを
     返すだけで値そのものではない(`Value` は Excel オブジェクトモデル上パラメーター付きプロパティの
     ため。`$cell.Value()` と明示的に呼ぶ必要がある)。`$cell.Value()` を正しく呼ぶと日付書式セルは
     `System.DateTime` になることを確認した。一方で「通貨を丸める」という従来の記述は今回の実測では
     裏付けられなかった(`19.999999` を `$#,##0.00` 書式で `.Value()` しても `System.Double` の
     `19.999999` のまま、丸めは発生しなかった)ため、その主張は削除し、実測できた 2 点
     (`PSParameterizedProperty` の罠・日付の `DateTime` 化)に絞って書き直した。
   - 結合セル(`C1:D1` を `Merge()`)は、アンカー(`C1`)に書いた値が `D1` からは `$null` で読める
     ことを確認。さらに `D1` へ直接 `Value2` を書き込んでも例外にはならないが、書き込み後も `D1` は
     `$null` のまま・`C1` の値も変化しない(＝サイレントな無視)ことを実測で新たに確認した(design doc
     時点では「アンカーにだけ書け」という指示のみで、非アンカーへ書いた場合の具体的挙動は未検証
     だった)。
   - 保護シート(`Worksheet.Protect('pw123')`)への書き込みは COM 例外を即座に投げることを確認
     (ローカライズされたメッセージ「変更しようとしているセルは保護されているシート上にあります…」)。
     `Unprotect` 後は書き込めること、再 `Protect` 後 `ProtectContents` が `$true` に戻ることも確認した。
   - スペース入りシート名(`My Data`)を **クォートせずに** `.Formula = '=My Data!A1'` を代入しても
     例外にはならず、そのままの文字列で `Formula` に保存され、`Value2` は `#NAME?` のエラーコード
     (`-2146826259`)になることを実機で新たに確認した(design doc 時点では「クォートが要る」としか
     書いておらず、「クォート漏れが例外になるのか静かに壊れるのか」は未検証だった)。クォートした
     `='My Data'!A1` は問題なく書き込めることも確認した。
   - 副産物として、`NumberFormat` の既定値が日本語ロケールでは `"General"` ではなく `"G/標準"` に
     なることも同じ実行で再確認した(T-06 の記録と一致)。
   - `skill/SKILL.md` の該当 4 項目(#1・結合セル・保護シート・スペース入りシート名)を上記の実測結果で
     書き直し、下記の採用一覧の出典欄に「本ラウンド実機検証」と明記した。
