### 実機で踏んだ COM の罠(SKILL.md gotchas 候補、S-05)

**既定(General)書式のセルに `Range.Value2` で数値に見える文字列("2024" など)を書き込むと、
Excel が自動的に数値([double])へ変換し、文字列のまま保持されない。** `Set-XlsRange` 自身は
`NumberFormat` を一切変更しない(仕様どおり)ため、これだけでは防げない。model.xlsx の
Year 見出し行(`"2024"`...`"2028"`、SKILL.md 財務モデル節が要求する「年は文字列として」)で
最初に踏んだ。実機で 4 パターンを比較して確認した:
- 既定書式のまま `Value2 = "2024"` → 読み戻すと `System.Double`(2024)になる(NG)。
- 書き込み**前**に対象セルへ `NumberFormat = '@'`(テキスト書式)を設定してから
  `Value2 = "2024"` → 読み戻すと `System.String`("2024")のまま(OK)。
- 先頭にアポストロフィを付けた `Value2 = "'2024"` → アポストロフィは値から取り除かれ、
  `System.String`("2024")として保持される(OK、書式が既定のままでも効く)。
- `NumberFormat = '@'` を先に設定した上でアポストロフィも付ける → 同じく `System.String`(OK、
  併用しても壊れない)。
NumberFormat を後から `'@'` に変えても、既に数値化された既存の値は文字列に戻らない(順序が
重要: 書き込みより前に設定する必要がある)。Make-Fixtures.ps1 では Year 見出し行に書き込む
直前に `$wsM.Range('A3:F3').NumberFormat = '@'` を設定する対処にした。
`skill/reference/com-constants.md`/`patterns.md` にはこの時点では未反映(fixtures 生成セッションの
担当範囲外のため。後述の手順 3 で patterns.md に反映済み — Codex r1 レビューの nit を受けて
時点を明記)。

もう 1 点、model.xlsx で最初に `='Assumptions'!$B$6` のように単純なシート名(スペース・
アポストロフィなし)を単引用符で囲んで書いたところ、Excel が保存前の読み戻し時点で単引用符を
自動的に取り除き(`=Assumptions!$B$6` に正規化)、`Set-XlsFormulaVerified` の完全一致検証が
常に失敗した。`skill/reference/patterns.md`「Named ranges」節に書かれている「クォート不要な
単純シート名だと Excel が単引用符を自動的に取り除く」という既知の挙動を数式(`Names.Add` の
`RefersTo` だけでなく `Range.Formula` でも同様)で追加確認した形になる。対処: シート名に
スペース/アポストロフィがない場合は単引用符を付けずに書く(`Assumptions!$B$6`)。
