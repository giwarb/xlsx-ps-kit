# T-07 Get-XlsOverview

## 目的
シート概観の Markdown ダンプ `Get-XlsOverview` を実装する(markitdown 相当。編集計画には使わせない)。

> 01-design.md §3.3:
> ```
> Get-XlsOverview -Path <string> [-Sheet <string[]>] [-MaxRows 50] [-MaxCols 30]
> ```
> - シートごとに `## SheetName` 見出し + Markdown 表。`Range.Text`(表示文字列)ベース。
> - 座標を出さない。SKILL.md で「編集計画には使うな」と書く。
> - `MaxRows/MaxCols` 超過は末尾に `... (N rows × M cols total)` を付ける。

## 入力
- 参照ファイル: docs/01-design.md §3.3、§7(既定 MaxRows/MaxCols は実装中判断)、docs/03-guardrails.md
- 前提タスク: T-06(完了済み)
- 前提レビュー: T-06 系(値変換の罠。ただし Overview は Range.Text ベースなので変換規則は再利用しない点に注意 — 表示文字列をそのまま出す)

## 仕様の具体化
- `-Path` を受けて内部で `Invoke-XlsSession -ReadOnly` を使う(呼び出し側は COM を見ない)。
- 各シートの UsedRange を対象に、`MaxRows`/`MaxCols` でクリップして Markdown 表を生成。
- `Range.Text` は範囲一括で取れない(単一セルずつ)可能性が高い — 設計は「表示文字列ベース」を要求している。性能と正確性のバランスは実装判断(例: 一括 Value2+NumberFormat で近似せず、クリップ後の小さな範囲に限りセル単位 Text を許容する等)。判断を実装メモに記録。
- Markdown 表のセル内のパイプ文字・改行はエスケープ。
- 空シートは `## SheetName` + `(empty)` などの明示。
- 戻り値は文字列(全シート連結)。

## 実装メモ(Sonnet が記入)

### 実装方針
- `Get-XlsOverview` は `Invoke-XlsSession -ReadOnly` の `ScriptBlock` 内で完結させ、呼び出し側に COM を
  一切見せない。`-Sheet` 未指定時はワークブックのタブ順、指定時は**指定した順序**（タブ順ではない）で
  出力する。
- 新規内部ヘルパー 3 つ（いずれも Export しない）:
  - `ConvertTo-XlsMarkdownTableCell`（純粋関数）: 1 セルの表示文字列を Markdown 表セルとして安全に
    埋め込める形にエスケープする。
  - `Get-XlsRangeTextGrid`（COM。Invoke-XlsSession の ScriptBlock 内から呼ばれる前提）: クリップ後の
    矩形をセル単位 `Cells.Item(r,c).Text` で読み、ジャグ配列にする。
  - `Format-XlsSheetOverviewMarkdown`（COM）: 1 シート分の `## SheetName` + 表（または `(empty)`）を
    組み立てる。

### 踏んだ罠・実機確認した挙動（S-05）
1. **`Range.Text` は複数セル範囲でも例外を投げない — しかし配列を返さない。** 実機で
   `$ws.Range('A1:B2').Text`（4 セルの値がすべて異なる）を呼ぶと、例外にならず戻り値の型が
   `System.DBNull` になることを確認した（`Range.NumberFormat` が範囲内で不統一のとき `DBNull` を
   返すのと同じ挙動）。つまり「範囲内のすべてのセルの表示文字列が完全に同一なら」その 1 個の文字列を
   スカラーで返し、1 つでも異なれば `DBNull`。複数セルの表示文字列を一括取得する経路は存在しないため、
   `Get-XlsOverview` は（クリップ後の範囲に限定した上で）常にセル単位 `Cells.Item(r,c).Text` を使う。
   タスクカードの「一括不可なら…セル単位を許容する」という前提を実機で裏取りした形。
2. **真に空白のシートの `UsedRange` は `$A$1`（1x1、`Value2=$null`、`Text=''`）。** 実機確認済み。
   これを「空シート」判定の唯一の根拠にした（`(empty)` を出す条件は「`UsedRange` が 1x1 かつ
   その唯一のセルの `Text` が空文字列」）。単一セルにのみ実データがあるシート（例: A1 だけに "X"）は
   この条件に当たらず、通常どおり見出し行のみ 1 行の表になる。
3. **列幅が狭いと `Range.Text` は `#`（オーバーフロー表示）を返す。** 実機で列幅 2、値
   `123456789.123` のセルの `Text` が `'#'` になることを確認した。`Get-XlsOverview` は
   「表示文字列ベース」という設計方針どおりこれをそのまま出す（Excel が実際に見せている文字列であり
   バグではない）。ただし、これは「概観は編集計画に使うな」という設計上の注意書きの実例そのものであり、
   SKILL.md の gotchas 候補としても良い（列幅次第で中身が読めないことがある）。
4. **`Worksheets.Add()` は既定でアクティブシートの手前に挿入される。** 新規追加シートが先頭寄りになり、
   タブ順が直感と逆になりうる（テストで確認）。`-Sheet` 未指定時の既定順はこの「実際のタブ順」に
   従うので、テストのシート追加順に依存した assertion を書かないよう注意した（`-Sheet` 指定時は
   要求した順を保証するテストで検証）。
5. **`` `u{00D7} `` Unicode エスケープは PowerShell 6.2+ の構文で 5.1 では使えない（G-11）。**
   最初この構文で書きかけて気づいた。`[char]0x00D7` で乗算記号 `×` を明示的に組み立てる方式に直した。
6. **Markdown 表セルのエスケープ順序**: バックスラッシュ → パイプ → 改行（CRLF/CR/LF いずれも
   リテラル 2 文字 `\n` に変換）の順で処理しないと、パイプ/改行エスケープで挿入した `\` 自身を
   二重エスケープしてしまう。バックスラッシュを最初に処理することで回避した。往復変換（エスケープを
   戻す）は非対応（概観専用・編集計画には使わない設計方針のため）。

### 実装判断（仕様に明記がないため記録。§7 対応）
- `MaxRows`/`MaxCols` の既定値は設計どおり 50/30。1 未満は Excel を起動する前にパラメーター検証で
  弾く（次の一手が分かる例外。Excel プロセスを無駄に起動しない）。
- クリップ後の範囲の**先頭行**を Markdown 表の見出し行としてそのまま使う（実際にヘッダーかどうかは
  問わない）。列番号由来のアルファベット見出し（A, B, C...）は「座標を出さない」という設計方針に
  反するため使わない。Markdown 表として構文的に妥当にするには見出し行が必要なため、シート先頭行を
  流用する。
- `... (N rows × M cols total)` の N/M は `UsedRange` の合計行数・合計列数（クリップ前）。行・列の
  どちらか一方でも上限を超えていれば出す。
- パイプ・改行のエスケープ方式は上記「踏んだ罠 6」のとおり。
- 空シートの扱いは上記「踏んだ罠 2」のとおり（1x1 かつ `Text` が空文字列）。
