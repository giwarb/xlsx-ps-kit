## 実装メモ(Sonnet が記入)

### やったこと

- `skill/scripts/XlsAgent.psm1` に Export しない内部ヘルパー 2 つを追加(T-03 の `Invoke-XlsSession` の土台)。
  - `Start-XlsApplication -Visible`: `New-Object -ComObject Excel.Application` で新規起動し、
    ワークブックなしで設定可能な初期状態(`Visible/DisplayAlerts/ScreenUpdating/EnableEvents/AskToUpdateLinks`)を設定して返す。
    起動前後の `Get-Process EXCEL` 差分で PID を特定し、戻り値の COM オブジェクトに `NoteProperty XlsAgentProcessId` として付与する。
  - `Stop-XlsApplication -Application -GraceSec 5`: `Quit → ReleaseComObject → GC×2` の後、
    `XlsAgentProcessId` が消えるまで `GraceSec` 秒だけ待ち、まだ残っていればそのPID **だけ** `Stop-Process -Force` する(G-10 準拠、全殺しではない)。
- `tests/T02.Tests.ps1` を新規作成。3 ケース:
  1. `Start-XlsApplication`/`Stop-XlsApplication` が Export されず、モジュールスコープ内には存在すること。
  2. 起動 → 初期状態確認 → 終了 → PID 差分ゼロの本編スモークテスト。
  3. `Start-XlsApplication` と `Stop-XlsApplication` の間で例外が飛んでも(呼び出し側の `finally` で片付ければ)残骸が出ないこと。
- 両ファイルとも UTF-8 BOM 付きで保存(T-01 の教訓、`[System.IO.File]::WriteAllText` + `UTF8Encoding($true)` で確認)。
- `$script:Xl` は空のまま維持(T-01 の「空の器」テストを壊さないため。理由は下記の罠を参照)。

### 踏んだ COM の罠(S-05)

1. **`Application.Calculation` はワークブックが1つも無いと設定できない。**
   `Workbooks.Count -eq 0` の状態で `$app.Calculation = xlCalculationManual(-4135)` を実行すると
   `Exception setting "Calculation": "Exception from HRESULT: 0x800A03EC"` で失敗する(実機で再現確認済み)。
   01-design.md §3.1 は「起動 → 初期状態設定(Calculation含む) → Workbooks.Open」の順で書かれているが、
   実際には Calculation の設定は **ワークブックを開いた後**でないと通らない。
   → T-02 では Calculation の設定・検証を対象から外した(`Start-XlsApplication` はこの5つのみ設定)。
   T-03 の `Invoke-XlsSession` では `Workbooks.Open/Add` の**後**に `Calculation` を設定すること。この罠は
   `$script:Xl.xlCalculationManual` を使わずに済んだため、`$script:Xl` は T-01 のまま空で維持した
   (充填は予定どおり T-13、または T-03 で実際に使うタイミングで追加)。
2. **`Quit()` → `ReleaseComObject`(戻り値 0 を確認)→ `GC.Collect()`×2 をしても、EXCEL.EXE プロセス自体は
   すぐには終了しないことがある。** 実機の隔離実験(他の Excel 呼び出しを一切挟まない単独計測)で、
   クライアント側の COM 参照をすべて解放した(`ReleaseComObject` の戻り値が 0)にもかかわらず、
   プロセスが実際に消えるまで **約 60.5 秒** かかったケースを観測した。参照リークではなく、
   Excel 側の終了処理が非同期・低優先度で行われるためと見られる。
   → 素朴な `Quit→Release→GC×2→即座にPID確認` ではテストが安定しない(実際に最初の実装でこれにより2回失敗した)。
   対策として `Stop-XlsApplication` に猶予秒数(既定5秒)のポーリング待ちを入れ、それでも残っていれば
   `Start-XlsApplication` が特定した **その PID だけ** を `Stop-Process -Force` するフォールバックを追加した
   (G-10 の「全殺し禁止」は `Get-Process EXCEL | Stop-Process` のような無差別停止の禁止であり、
   自分が起動したと分かっている単一 PID を狙い撃ちする強制終了はこの禁止の対象外と解釈した)。
3. **強制終了の直後、ベースラインにも起動 PID 一覧にも無い「別の」EXCEL.EXE が一瞬だけ現れることがある。**
   Office の次回起動を早めるためと思われる裏プロセスらしく、数百 ms 以内に自然に消える。
   単発の PID 比較(`Get-ExcelPids` を1回呼ぶだけ)だとこれを拾ってフレーキーに失敗する。
   → テスト側の最終確認をポーリング化(最大10秒、ベースラインへの収束を待つ)して安定させた。
4. (再確認)COM オブジェクトも PowerShell 上では `PSObject` にラップされているため、
   `Add-Member -NotePropertyName ... -Force` で独自メタデータ(起動時に特定した PID)を安全に付与できる。
   `Stop-XlsApplication` はこれを使って「自分が起動した PID」を Quit 後も追跡している。
5. (再確認、T-01 の教訓どおり)`.ps1`/`.psm1` は UTF-8 **BOM 付き**で保存しないと、
   PowerShell 5.1 が日本語コメントを含むファイルの構文解析でエラーになる。今回も編集後に毎回バイト列を確認した。

### レビュー指摘への対応（round 1、harness/state/reviews/T-02.md）

1. **[blocking] PID 差分は「自分が起動したプロセス」の証明にならない** → **対応した**。
   `Start-XlsApplication` の PID 特定方法を「起動前後の `Get-Process EXCEL` 差分」から
   「`Application.Hwnd` を `GetWindowThreadProcessId`（P/Invoke, `XlsAgent.NativeMethods`）で
   解決した PID」に置き換えた。あわせて `Get-Process -Id $ownerPid` でプロセス名が `EXCEL` であることを検証し、
   `StartTime`（UTC Ticks）を `XlsAgentProcessStartTicks` として PID とセットで記録するようにした。
   `Stop-XlsApplication` は強制終了の直前に `Get-Process -Id $targetPid` の `StartTime` が記録済みの
   Ticks と一致するかを再確認し、一致しなければ（PID 再利用の疑いがあれば）強制終了せず fail closed で
   `throw` するようにした（レビューのコード例をほぼそのまま採用）。差分方式は撤去済み。
2. **[should-fix] 起動・終了途中の例外で COM の解放処理を飛ばす** → **対応した**。
   `Start-XlsApplication` は本体を `try` で包み、`catch` で（`$app` が存在すれば）`Quit`（失敗は握りつぶす）→
   `IsComObject` 確認の上 `ReleaseComObject` → `GC.Collect/WaitForPendingFinalizers` ×2 を実行してから
   例外を再送出するようにした。`Stop-XlsApplication` は `$Application.Quit()` を `try`、
   `Release`＋`GC×2` を `finally` に移し、`Quit()` が例外を投げても後始末に必ず到達するようにした。
3. **[should-fix] 強制終了の失敗を成功扱いして返す** → **対応した**。
   `Stop-Process -Id ... -Force -ErrorAction SilentlyContinue` を
   `Stop-Process -InputObject $target -Force -ErrorAction Stop` に変更し、失敗を握りつぶさないようにした。
   実行後は最大 5 秒ポーリングして消滅を確認し、それでも残っていれば
   `throw "Owned Excel process PID $targetPid did not terminate after Stop-Process."` するようにした。

対応後、`tests/T02.Tests.ps1` を 2 回連続実行しどちらも 3/3 緑、`tests/T01.Tests.ps1` も 13/13 緑（回帰なし）。
毎回 `Get-Process EXCEL` で残骸ゼロを確認した。
