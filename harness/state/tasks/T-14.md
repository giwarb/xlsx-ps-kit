### 各パターンの結果要約(すべて 2026-08-18 実機確認、patterns.md に詳細記録)

2. テーブル化(ListObjects.Add): SourceType=1(xlSrcRange)、HeaderRowRange の値が一致。
3. 列幅自動調整: AutoFit 前後で ColumnWidth が 8.38→50.5 に変化（フォント・テーマ依存の実測値であり
   一般化はしない、と patterns.md に明記）。
4. コメント追加: **AddComment（レガシー）と AddCommentThreaded（スレッド形式）の両方がこの環境
   （Excel Build 20228）で問題なく動作した**。タスクカードが想定していた「動かない場合」には
   該当しなかったが、その事実（動いたこと・ビルド番号）自体を patterns.md に記録した。
5. 条件付き書式: FormatConditions.Add の Type=1(xlCellValue)/Operator=5(xlGreater) とも一致。
6. データ検証(リスト): Validation.Type=3(xlValidateList)、AlertStyle=1(xlValidAlertStop) を確認。
   round 1 時点では AlertStyle が com-constants.md に個別の行がなかったため patterns.md 側の確認記録を

7. グラフ挿入(round 1 時点): ChartType=51(xlColumnClustered)→4(xlLine) の代入・読み戻し一致。

   ※ round 2 のレビュー対応でスニペットから Delete() を除いたため、この結果は現在の patterns.md の
   内容とは異なる（下記参照）。
8. 名前定義(round 1 時点): Names.Add に単引用符付きシート名で RefersTo を渡したところ、読み戻すと
   Excel がクォート不要と判断して単引用符を自動的に除去した文字列（`=Sheet1!$A$1`）になっていた。
   「渡した文字列がそのまま RefersTo に残るわけではない」という罠として patterns.md に明記した。
   ※ round 2 でシート名を変えて再実測している（下記参照）。
9. シート追加・複製・削除: Worksheets.Count が Add で 1→2、Copy で 2→3、Delete で 3→2 と正しく推移。

### 踏んだ罠
- `Range.Value2` は**複数セル範囲への書き込みは 0-based の `[object[,]]`** だが、**同じ範囲を
  読み戻すと 1-based** になる（`XlsAgent.psm1` の `New-XlsObjectArray2D` の実装メモに既にある
  非対称性と同じもの）。検証スクリプトの最初のドラフトで `$hdr.Value2[0,0]` のように書き込み側と
  同じ 0-based で読もうとして `IndexOutOfRangeException` を踏んだ。`[1,1]` に直して解消。
  patterns.md のパターン 1・2 の確認欄に明記済み。
- `Names.Add` の `RefersTo` はシート名にクォートを付けて渡しても、読み戻すとクォート不要な場合は
  Excel 側で自動的に外される（パターン 8）。エージェントが書き込んだ文字列と読み戻し文字列の完全一致を
  前提にした検証コードを書くと失敗しうる。

### レビュー指摘への対応(harness/state/reviews/T-14.md round 1、判定 fix。G-16)

- **[blocking] Value2 スカラー代入 4 箇所(AutoFit/コメント×2/名前定義)** → 対応した。
  AutoFit と名前定義は 1×1 の `[object[,]]` に変更（`$data = New-Object 'object[,]' 1,1; $data[0,0] = ...`）。
  コメント 2 箇所はセル値代入自体（`Value2 = 'legacy'` / `'threaded'`）を削除した（コメント動作の確認に
  セル値は不要なため）。4 箇所とも `verify-fixes.ps1`（使い捨て、フォアグラウンド）で再実行し、
  `patterns.md` の確認欄を更新済み（AutoFit: `Before/After/Val` を読み戻し。コメント: `.Text()` の
  読み戻しが変更前と同じ値であることを確認。名前定義: 下記参照）。
- **[should-fix] グラフ挿入スニペットが Delete() で成果物を残さない** → 対応した。公開スニペットから
  `ChartObject.Delete()` を削除し、`ChartObjects().Add(...).Chart` を 1 行にまとめて 10 行に短縮
  （レビュー提示のコード例と同じ形）。確認欄を「実行前後の `ChartObjects().Count` が `0`→`1`」
  「`ChartType` 読み戻しが `51`」に更新し、グラフを削除せず残す運用に変えたことを明記した。
- **[should-fix] データ検証の Operator にマジックナンバー、xlValidAlertStop が com-constants.md 未収載**
  → 対応した。`Validation.Add` の第 3 引数（Operator）を `3` から `[Type]::Missing` に変更し再実行。
  `xlValidAlertStop=1` を `skill/reference/com-constants.md`（条件付き書式・データ検証の節）に、
  実測方法（`Validation.Add(3, 1, [Type]::Missing, 'A,B,C')` 実行後の `AlertStyle` 読み戻し）付きで
  追加した。`patterns.md` の一次資料の記述も「com-constants.md にある」に修正した。
- **[should-fix] AutoFit の説明・名前定義のクォート記述が実測範囲を超えている** → 対応した。
  AutoFit は「`Worksheet.Columns` が返すのは Range であり、`AutoFit()` は行・列を表す Range に
  対するメソッド」と正確化した。名前定義は、シート名を `Sheet1` からスペースと単引用符を含む
  `"Sales O'Brien Q1"` に変えて再実測し、`.Replace("'", "''")` によるクォート二重化を追加した
  スニペットに変更した。読み戻した `RefersTo` は渡した文字列と完全一致し、round 1 で見られた
  「クォート不要な単純シート名では Excel が単引用符を自動的に外す」という正規化はこのケースでは
  起きなかったことを確認欄に明記した（`Sheet1` の場合との違いという形で、一般化せず両方の実測事実を
  残した）。
