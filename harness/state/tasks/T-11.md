# T-11 外部リンク検出と refused / -Force

## 目的
`Test-XlsFormulas` に外部リンク検出を追加する。リンク元ファイルが存在しない場合は再計算せず `refused` を返し、`-Force` で続行する。

> 01-design.md §3.6:
> - 外部リンク(`$wb.LinkSources(xlExcelLinks)` が非 null)があり、リンク元ファイルが存在しない場合は
>   `{ "status": "refused", "reason": "external links present", "links": [...] }` を返して**再計算しない**。`-Force` で続行。
> - SKILL.md の対応記述: 「refused のときはリンク値の退避(Get-XlsRange)か -Force を選ぶ。リンクを黙って壊さない」

## 入力
- 参照ファイル: docs/01-design.md §3.6、docs/03-guardrails.md G-04
- 前提タスク: T-10(完了済み)、T-08(LinkSources の実機挙動が実装メモに記録済み)
- 前提レビュー: T-10 系

## 仕様の具体化(実装判断は実装メモに記録)
- 判定タイミング: CalculateFullRebuild の**前**。refused の場合は再計算せずに返す(再計算するとリンクセルが #REF! になり、保存はしないが検証結果が汚れるため)。
- refused 条件: LinkSources(xlExcelLinks) が非 null かつ、そのうち 1 つでも存在しないパスがある場合(全リンク先が存在するなら通常フローで続行 — 設計の「リンク元ファイルが存在しない場合」を素直に読む)。
- links フィールド: LinkSources の返す全リンクパス(存在するものも含むか、欠損のみか、は実装判断 — recalc.py 互換の観点で JSON 構造が {status, reason, links} であることが契約。判断を記録)。
- -Force: T-01 以来スタブに存在する既存パラメータを配線。refused 判定をスキップして通常の検証フローを実行。
- refused は正常系(エラーではない)。exit code の扱いは T-12。

## 受け入れテスト要点(02-implementation-plan.md §4)
- 存在しない `C:\nonexistent\...` へのリンクを持つブック(T-08 のテストで確立した作成手法を再利用)で `refused` が返り、reason/links キーが契約どおり。
- refused のとき再計算が走っていないこと(検証方法は実装判断: 例えば stale キャッシュを仕込み、refused 後も Value2 が古いままであることを T-10 の New-XlsxWithStaleFormulaCache で確認)。

- リンクなしブックでは従来どおり(T-10 の既存テストが回帰として機能)。

## 実装メモ(Sonnet が記入)

### 実装した内容
- `skill/scripts/XlsAgent.psm1`
  - `Get-XlsExternalLinkStatus -Workbook <obj>`(内部、Export しない)を新設。
    `Workbook.LinkSources(xlExcelLinks)` を読み、リンクパス一覧(`Links`)と、そのうち 1 つでも
    `Test-Path -LiteralPath` で存在しないものがあるか(`HasMissing`)を返す。T-08 の
    `Get-XlsModel` の `workbook.links` 構築コードと同じ COM 呼び出し・同じ値を再利用する形にした。
  - `Test-XlsFormulas` のスクリプトブロック冒頭(`Set-XlsCalculationAutomatic` の**前**)に、
    `-Force` でなければ `Get-XlsExternalLinkStatus` を呼び、`HasMissing` が真なら
    `{ status: "refused", reason: "external links present", links: [...] }` を返して即座に抜ける
    (`Set-XlsCalculationAutomatic`/`CalculateFullRebuild`/エラー走査のいずれも実行しない)。
    `-Force` のときはこの判定自体を呼ばず、常に通常フロー(既存の success/errors_found)に進む。

### 仕様の具体化(実装判断)
- **判定タイミング**: タスクカード指定どおり `CalculateFullRebuild`(`Set-XlsCalculationAutomatic`
  の内部で呼ばれる)より前。`Get-XlsExternalLinkStatus` は `LinkSources` の読み取りと
  `Test-Path`(ファイルシステムのみ、COM ではない)だけで完結し、再計算を一切要求しない。
- **refused 条件**: `LinkSources(xlExcelLinks)` が非 null かつ、そのうち 1 つでも
  `Test-Path -LiteralPath` で存在しないパスがある場合。全リンク先が存在する場合はリンクが
  あっても refused にせず通常フローで続行する(実機テストで確認、下記「踏んだ COM の罠」参照)。
- **`links` フィールドの内容**: LinkSources が返す全リンクパスを含める(存在するものも含む。
  欠損分だけに絞らない)。理由:
  1. T-08 `Get-XlsModel` の `workbook.links` が既に「LinkSources の生の全件」という契約で
     実装・テスト済みであり、同じ COM 呼び出し・同じ値を refused でも再利用することで
     挙動を一貫させた(実装を分岐させない)。
  2. 「欠損分だけ」にすると「存在するリンクは省略する」という新しい絞り込みルールを別途
     定義・文書化する必要が生じ、エージェントが `Get-XlsModel.workbook.links` と
     `Test-XlsFormulas` の refused `links` を異なる意味だと誤解する余地が増える。
  3. refused を見たエージェントが SKILL.md の指示(「リンク値の退避(`Get-XlsRange`)か
     `-Force` を選ぶ」)に従って対応する際、どのリンクが対象かの全体像が 1 個のフィールドで
     揃う方が扱いやすい。
- **`-Force`**: T-01 以来のスタブパラメータを配線した。refused 判定(`Get-XlsExternalLinkStatus`
  の呼び出し自体)をスキップし、常に通常フロー(success/errors_found、リンク切れセルは
  `CalculateFullRebuild` 後に `#REF!` として通常のエラー検出に自然に乗る)を実行する。
- **refused は正常系**: `-AsJson` でも `{status, reason, links}` の 3 キーのみを JSON 化する。
  success/errors_found の形(`status/total_formulas/total_errors/error_summary`)とは別物であり、
  refused の結果オブジェクトには total_formulas 等のキーを一切含めない(テストでキー集合を
  `'links,reason,status'` に固定。success/errors_found 側のキー集合
  `'error_summary,status,total_errors,total_formulas'` も `-Force` 込みで変わらないことを固定した)。
- **`-TimeoutSec`**: 引き続き未配線(T-12 の CLI 層の範囲。本タスクでは触っていない)。

### 実機確認したこと(プローブ実行、Invoke-XlsSession 経由)
- `LinkSources(xlExcelLinks)` はリンク数が 1 件でも常に `System.Object[]`(1-based)で返る
  (`Value2`/`NumberFormat` に見られる「1 件ならスカラー化」パターンにはならない。T-08 の
  「1-based string[]」という記録を、要素数 1 のケースでも追加確認した)。
- 要素は `[シート名]` やセル参照部分を含まないプレーンなファイルパス
  (`='C:\NoSuch\[Other.xlsx]Sheet1'!A1` という数式に対して `C:\NoSuch\Other.xlsx` が返る)。
  `Test-Path -LiteralPath` でそのまま存在確認できる。
- リンク先が実在するファイルの場合も同じ形(プレーンなパスの `string[]`)で `LinkSources` に
  含まれる(解決済み・未解決を問わない)。この場合 `Test-Path` は真になり、対応するセルの
  `Value2` はリンク先の実際の値(検証用に作ったファイルでは `42`)を正しく返した
  ("does not refuse when every external link source resolves to an existing file" テストで確認)。

### 「refused のとき再計算していない」ことの検証方法(実装判断、round 1 レビュー should-fix 対応で記述を修正)
ブラックボックス視点では、`Test-XlsFormulas` は常に `-ReadOnly` セッションで保存しないため、
「再計算だけして保存しない」場合と「再計算そのものをしない」場合はディスク上のファイルからは
区別できない。したがって実行可能なテストだけで refused 側の未再計算を直接証明することはできない。
裏付けは 2 種類の性質が異なる根拠を組み合わせたもの:
1. **テストで固定した回帰**: refused の戻り値の形を `{status, reason, links}` の 3 キーだけに
   固定した(テストで `PSObject.Properties.Name` のキー集合を明示比較)。`total_formulas`/
   `error_summary` 等の「`CalculateFullRebuild` を経て初めて埋まる情報」を一切含まないことを
   回帰として固定した。
2. **コードレビュー(実行では確認できない、コード順序による保証)**: `skill/scripts/XlsAgent.psm1`
   の `Test-XlsFormulas` では、`Get-XlsExternalLinkStatus` による refused 判定と早期 `return` が
   `Set-XlsCalculationAutomatic`(= `CalculateFullRebuild` を含む)の呼び出しより**前**の行に
   書かれている。したがって refused を返す実行パスはエラー走査コードにそもそも到達せず、
   `CalculateFullRebuild` は呼ばれない。これはコード上の事実であり、テストで動的に検証している
   ものではない(round 1 レビュー should-fix 指摘: 「stale cache + `-Force` の対比だけでは
   refused 側の未再計算を証明できない」への対応。誤って実装が先に `CalculateFullRebuild` を
   呼んでから refused を返しても、`-ReadOnly` セッションは保存しないため、その後 `-Force` で
   同じ stale fixture を新しいセッションで開いた結果は変わらず、対比テストだけでは誤実装を
   検出できないという指摘は妥当だった)。
3. **`-Force` との対比テスト**(`tests/Test-XlsFormulas.Tests.ps1` の
   "`-Force` skips the refused check and performs a real recalculation, revealing a stale-cache
   error"): これが証明するのは「`-Force` を指定すると実際に `CalculateFullRebuild` に到達し、
   T-10 の `New-XlsxWithStaleFormulaCache` で仕込んだ stale cache(A1: 5→0 に ZIP 直接書き換え、
   A2=`100/A1` のキャッシュ済み `<v>` は 20 のまま)が正しく再計算されて `#DIV/0!` として検出
   される」ことであり、「refused 側が未再計算である」ことの証明ではない(このテストの目的を
   誤解しないよう、テスト名・コメントから「refused の未再計算を実証する」という表現を削除し、
   「`-Force` が `CalculateFullRebuild` に到達することを確認する」という証明範囲に修正した)。

### 踏んだ COM の罠 / 気づいたこと(実機確認)
1. **LinkSources は 1 件でもスカラー化しない**: T-08 の記録は複数リンクのケースのみだったが、
   本タスクで単一リンクのケースもプローブで確認し、`Area.Value2`/`NumberFormat` のような
   「1 件ならスカラー」パターンとは異なることを確定させた(`com-constants.md` に追記)。
2. **LinkSources のパスは常にプレーン**: 数式内の `[Other.xlsx]Sheet1` という角括弧付きシート
   参照ではなく、`C:\...\Other.xlsx` という素のファイルパスが返る。`Test-Path -LiteralPath` を
   そのまま使える(追加のパース処理は不要)。
3. **既存の `Set-XlsFormulaVerified`/`Set-XlsValue2Verified`/`New-XlsxWithStaleFormulaCache`
   (T-10 のテストヘルパー)は無改造で外部リンク fixture にもそのまま使えた**。外部リンク数式
   ("='C:\...\[Other.xlsx]Sheet1'!A1")を `Set-XlsFormulaVerified` で書き込んでも、単一セルの
   読み戻し比較で問題なく一致した(プローブ・テストの両方で確認。数式文字列がそのまま
   ラウンドトリップし、Excel 側で正規化・書き換えされることはなかった)。

## round 1 レビュー対応(G-16、harness/state/reviews/T-11.md)

判定: done(blocking ゼロ)。should-fix 1 件・nit 1 件、いずれも対応した。

1. **[should-fix] stale cache と `-Force` の対比だけでは refused 側の未再計算を証明できない**
   → 対応した。指摘のとおり、`-ReadOnly` セッションは保存しないため「再計算だけして保存しない
   誤実装」と「再計算そのものをしない正しい実装」はディスク上のファイルからは区別できず、
   対比テストだけでは誤実装を検出できない。レビューの diff スニペットどおり:
   - `tests/Test-XlsFormulas.Tests.ps1` のテスト名を
     `'-Force skips the refused check and performs a real recalculation, revealing a stale-cache
     error the refused call never computed (proves refused truly skips CalculateFullRebuild)'` から
     `'-Force skips the refused check and performs a real recalculation, revealing a stale-cache
     error'` に変更(「refused の未再計算を実証する」という言い過ぎた主張を削除)。
   - 同テスト内のコメントを「この対比は refused の未再計算を実証する」という表現から、
     「この対比は `-Force` が `CalculateFullRebuild` に到達することを確認するためのもの」
     「refused 側の未再計算は、早期 return が `Set-XlsCalculationAutomatic` より前にあるコード順序
     そのもので保証されている」という証明範囲の正確な記述に修正。
   - 本タスクカードの該当記述(旧 94 行目付近、「『refused のとき再計算していない』ことの
     検証方法」節)も同様に、テストによる動的証明とコードレビューによる静的な保証を明確に
     区別する記述に書き換えた(上記の節を参照)。
2. **[nit] existing と missing が混在する 2 リンクの fixture を固定していない** → 対応した。
   `tests/Test-XlsFormulas.Tests.ps1` に新規 It
   `'includes both existing and missing external link sources in links when a workbook mixes the
   two (refuses because at least one is missing)'` を追加。既存リンク先(実ファイル、A1)と

   `links` に両パスが(欠損分だけに絞らず)含まれることをレビューのスニペットどおり
