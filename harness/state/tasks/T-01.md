## 実装メモ（Sonnet が記入）

- 成果物: `skill/scripts/XlsAgent.psm1`（骨組み・8 関数スタブ）、`tests/Common.ps1`
  （`Get-ExcelPids` / `Assert-NoOrphanExcel` / `New-TempXlsxPath`）、`tests/T01.Tests.ps1`。
- 公開関数の数について: タスクカード本文・harness/prompts の指示に列挙された名前は
  `Invoke-XlsSession / Save-XlsWorkbook / Get-XlsOverview / Get-XlsModel / Get-XlsRange /
  Set-XlsRange / Test-XlsFormulas / Clear-XlsOrphans` の 8 個。docs/01-design.md §3 は見出しが
  3.1〜3.6 の 6 節だが、3.5 が `Get-XlsRange`/`Set-XlsRange` の 2 関数を含むため実体は 7 関数
  ＋ guardrails G-02/G-10 が要求する `Clear-XlsOrphans` で合計 8。G-02 の「§3 の 6 つ（＋
  Clear-XlsOrphans）」という表現は見出し数（6）を指しており、実関数数（7＋1=8）とは一致しない。
  01-design.md §0 の確定事項には触れていないため、G-01 の「止まる」条件には該当しないと判断し、
  8 関数すべてを Export する形で実装した。数の食い違いに気づいた場合はレビューで指摘してほしい。
- 各関数は `[CmdletBinding()]` + docs/01-design.md §3 のシグネチャに沿った `param()` と
  コメントベースヘルプ（S-03）のみを持ち、本体は `throw '... は未実装です（T-XX で実装予定）。'`
  のスタブ。COM には一切触れていない。
- `$script:Xl = @{}` を定数表の器として用意（中身は空、T-13 で充填）。
- 踏んだ罠（COM gotchas ではないが今後の実装者向け）:
  1. **スクリプトファイルの文字コード**: `Write` ツールで UTF-8 (BOM なし) で保存すると、
     Windows PowerShell 5.1 はスクリプトを実行時のシステム ANSI コードページ（日本語環境では
     Shift-JIS 相当）で読むため、日本語コメント内のマルチバイト文字が文字化けし、その結果
     文字列リテラル境界が壊れて `Unexpected token ... in expression or statement.` という
     パースエラーになった。UTF-8 **BOM 付き**で保存し直して解消。`.ps1`/`.psm1` を書く際は
     必ず BOM 付き UTF-8 にすること（S-01 の「-Encoding UTF8」はデータ入出力だけでなく
     スクリプト保存にも当てはまる）。
  2. **空配列を返す関数が `$null` になる**: `function Get-ExcelPids { @(Get-Process ...) }` は
     ヒットが 0 件のとき、関数の戻り値が空配列ではなく `$null` になる（PowerShell はパイプ
     ラインに 0 個のオブジェクトが流れると呼び出し元に `$null` を渡す）。呼び出し側
     `Assert-NoOrphanExcel -Baseline (Get-ExcelPids)` が `[int[]]` パラメータへの
     `ParameterBindingValidationException` で落ちた。`return ,@(...)`（単項カンマで 1 個の
     配列オブジェクトとしてパイプラインに流す）で回避。
  3. **上記の回避策を呼び出し側でさらに `@()` で包むと二重ラップになる**: `Get-ExcelPids` を
     `,@(...)` で返すよう直した後、呼び出し側で `$current = @(Get-ExcelPids)` と書いたところ、
     空集合のときに `$current` が「空配列 1 個を要素に持つ長さ 1 の配列」になり、
     `Assert-NoOrphanExcel` が実在しない孤児プロセス（要素の文字列表現が `System.Object[]`）を
     誤検知した。`,@()` で防御的に配列化した関数の戻り値は、呼び出し側では素で受け取り
     （`$current = Get-ExcelPids`）、追加の `@()` を被せないこと。
- `Invoke-Pester -Path tests\T01.Tests.ps1` 実行結果: **Passed: 13, Failed: 0, Skipped: 0,
  Pending: 0, Inconclusive: 0**（実行環境 PowerShell 5.1.26100、Pester 3.4.0）。テスト中に
  Excel は一切起動していない（`Get-ExcelPids` は常に空集合）ため `Assert-NoOrphanExcel` は
  差分ゼロで通過。

## レビュー対応（round 1 → r2, G-16）

`harness/state/reviews/T-01.md`（判定 `fix`）の指摘 2 件への対応:

1. **[blocking] `Set-XlsRange` の必須択一シグネチャが未実装** — **対応した**。
   `-Data` / `-FromCsv` / `-FromJson` をそれぞれ `ParameterSetName`（`ByData` / `ByCsv` /
   `ByJson`）付き `Mandatory=$true` に変更し、レビューの修正案どおりにパラメーターバインドで
   択一を強制するようにした（`skill/scripts/XlsAgent.psm1` の `Set-XlsRange`）。`-Worksheet` /
   `-Range` / `-Header` はどの ParameterSet でも使うため `ParameterSetName` を付けていない
   （既定の `__AllParameterSets` のまま）。
2. **[should-fix] スタブのテスト名とアサーションが一致しない** — **対応した**。
   `tests/T01.Tests.ps1` の `It "stub function '$fn' throws ..."` を、レビューの修正案どおり
   `$cmd.ScriptBlock.Ast.Find(...)` で `ThrowStatementAst` の存在を検査する形に変更し、テスト名も
   `"stub function '$fn' contains an explicit throw"` に修正。`Get-Command` の非 null 確認だけの
   重複（Export テストと同義）を解消した。
3. re-run: `Invoke-Pester -Path tests\T01.Tests.ps1` → **Passed: 13, Failed: 0**（PowerShell
   5.1.26100 / Pester 3.4.0）。実行前後とも EXCEL.EXE PID なし。

レビューのチェックリストで `-`（該当なし）だった項目は T-01 のスコープ外（COM 未実装のため）と
判断し、変更していない。
