# T-08 Get-XlsModel

## 目的
数式と値を 1 回で取得するモデルダンプ `Get-XlsModel` を実装する(xlsx スキルの「2 回ロード」の代替)。

> 01-design.md §3.4:
> ```
> Get-XlsModel -Path <string> [-Sheet <string[]>] [-Range <string>] [-FormulasOnly] [-AsJson]
> ```
> - 返却(オブジェクト or JSON):
>   ```
>   {
>     workbook: { path, sheets: [name], names: [{name, refersTo}], links: [string], version, build },
>     sheets: [{
>       name, usedRange, tables: [{name, range}], protected,
>       cells: [{ address, formula, value2, numberFormat }]   // FormulasOnly なら数式セルのみ
>     }]
>   }
>   ```
> - `-Range` 指定時は該当範囲のみ。既定はシート全体の UsedRange。
> - SKILL.md で「まず `-FormulasOnly` か `-Range` で絞れ、全部取ると溢れる」と書く。

## 仕様の具体化(実装判断は実装メモに記録)
- `-Path` を受けて内部で `Invoke-XlsSession -ReadOnly`。
- cells の formula: `Range.Formula`(数式でないセルは値の文字列表現が返る点に注意 — 数式セルの判定は `HasFormula` か Formula が '=' 始まりか、方式を実装判断)。
- value2: T-06 の変換規則(ISO 日付、エラー文字列、$null)を再利用。
- numberFormat: 表示用でなく書式文字列そのもの。
- names: Workbook レベルの名前定義(name, refersTo)。シートスコープの名前の扱いは実装判断。
- links: `$wb.LinkSources(xlExcelLinks)`(非 null なら文字列配列)。定数 xlExcelLinks=1 を $script:Xl へ。
- tables: `ws.ListObjects`(name, range)。
- protected: `ws.ProtectContents`。
- version/build: `$app.Version` / `$app.Build`。
- 一括読み(Formula / Value2 / HasFormula の範囲一括)を基本にし、セル単位ループを避ける。NumberFormat は T-06 の 2 段構え(一括→混在時のみセル単位)を再利用。
- `-FormulasOnly`: 数式セルのみに絞る。`SpecialCells(xlCellTypeFormulas)` を使う場合はヒットなし例外を握りつぶす(G 候補、S-7)。使わず一括配列から絞ってもよい(実装判断)。
- `-AsJson`: JSON 文字列で返す(ConvertTo-Json の Depth 注意)。既定はオブジェクト。
- 空セル(値も数式もない)は cells に含めない(サイズ抑制)。含めるかどうかは実装判断だが、方針を実装メモに記録。

## 実装メモ(Sonnet が記入)

### 数式セルの判定方式（実装判断）
`Range.Formula` の `'='` 始まり判定ではなく `SpecialCells(xlCellTypeFormulas)` を採用した。
実機確認: セルに先頭アポストロフィで強制的にテキスト化した値（例 `'=5`）を入れると、
`Value2`/`Formula` はどちらも `"=5"` を返すが `HasFormula` は `$false` になる。`'='` 始まり判定だと
これを誤って数式セルと判定してしまう（`ConvertTo-XlsModelCellList` のテスト
「does not misclassify an apostrophe-forced text cell...」で固定）。

`HasFormula` 自体は複数セル範囲に対して一括取得すると、範囲内が全数式/全非数式なら `[bool]` スカラー、
混在なら `[DBNull]` を返す（`NumberFormat`/`Text` と同じ「一様なら 1 値、混在なら DBNull」パターン）。
セルごとの真偽値配列としては取得できないため、`HasFormula` を直接使う場合も結局セル単位のフォール
バックが必要になる。そこで `SpecialCells(xlCellTypeFormulas)` で「数式セルの集合」を 1 回の COM 呼び
出しで取得し、その `Areas`（矩形の集まり、`Area.Row/Area.Column` はシート上の絶対座標であることを
実機確認）を展開して `"row,col"` 文字列の `HashSet` を作る方式にした（`Get-XlsFormulaCellKeySet`）。
Areas の展開はメモリ上のループのみで追加の COM 呼び出しを含まないため、G-06 の「セル単位ループを
避ける」方針には反しない。ヒットなし（範囲内に数式セルが 1 つもない）は HRESULT 0x800A03EC の例外に
なることを実機確認し、S-7 どおり握りつぶして空集合にした。

### 踏んだ COM の罠
1. **`Range.Formula` の一括読み**: 複数セル範囲では `Value2` と同じ 1-based `[,]` 2 次元配列で返る。
   数式でないセルは「値の文字列表現」（例: 数値 42 のセルは `"42"`、文字列 "hello" のセルは
   `"hello"`）が入っており、これをそのまま `formula` フィールドに使ってはいけない（タスクカードの
   警告どおり）。数式セルの判定は上記の `SpecialCells` 方式で別途行う。
2. **`Range.HasFormula` の一括読み**: 複数セル範囲に対しては `NumberFormat` と同じ「一様なら
   スカラー `[bool]`、混在なら `[DBNull]`」パターンで返り、`Value2`/`Formula` のようなセルごとの
   配列にはならない（実機確認）。範囲全体のセルごとの真偽値を安く取るには不向きなため、この関数では
   使わず `SpecialCells` を採用した。
3. **`SpecialCells(xlCellTypeFormulas)` のヒットなし例外**: 実機で HRESULT `0x800A03EC`
   （`該当するセルが見つかりません。`）を確認。S-7 どおり `try/catch` で握りつぶし、空の `HashSet`
   を返す。
4. **`SpecialCells` の `Areas`**: 複数の不連続な数式セル領域がある範囲では `Areas.Count` が 2 以上に
   なる（実機確認、A1:B4 に A2, A4 だけ数式があるケースで `Areas.Count=2`）。各 `Area.Row`/
   `Area.Column` はシート上の絶対座標（呼び出し元の Range がシートのどこにあっても変わらない）。
5. **`Workbook.LinkSources(xlExcelLinks)` の戻り値**: リンクなしは `$null`。リンクありは 1-based の
   `string[]`（`Value2`/`Formula` の 2 次元配列や既存の `Get-XlsRange` の知見と同じく、複数セル/複数
   要素の COM 配列は 1-based で marshaling される）。存在しない外部ファイルへの数式リンク
   （`='C:\NoSuch\[Other.xlsx]Sheet1'!A1`）を作って `Save-XlsWorkbook` で保存・再オープンしても、
   `Formula` はリンク文字列を保持したまま、対象セルの `Value2` は `#REF!` エラー値になり、
   `LinkSources` は解決できないリンク先のパスをそのまま返すことを実機確認した。
6. **`Workbook.Names` にシートスコープの名前が混ざる**: シートスコープで追加した名前
   （`Worksheet.Names.Add`）も `Workbook.Names` コレクションに現れるが、`.Name` プロパティが
   `"SheetName!Name"` という形式になる（実機確認）。ワークブックレベルの名前だけを `workbook.names`
   に含めるため、`.Name` に `!` を含むものを除外した（Excel はシート名に `!` を許可しないため、この
   判定は安全）。
7. **`[int]` キャストは四捨五入であって切り捨てではない**（`ConvertTo-XlsColumnLetter` で踏んだ）:
   桁上がり計算で `$n = [int](($n - 1) / 26)` と書いたところ、`(26-1)/26 = 0.9615...` が `[int]`
   キャストで `1` に丸められてしまい、26 の倍数の列（26=Z, 52=AZ, 702=ZZ）で 1 桁多い誤った文字列
   （Z→AZ, AZ→BZ）を生成するバグを Pester で検出した。`[Math]::Floor` で明示的に切り捨てるよう修正
   （`$n` は常に正なので `Floor` と `Truncate` は同じ結果）。SKILL.md gotchas 候補。
8. **`HashSet[string]` を `return` するときの単項カンマ忘れ**: `Get-XlsFormulaCellKeySet` で
   `return $keySet`（単項カンマなし）と書いたところ、`HashSet` が `IEnumerable` を実装しているため
   PowerShell の出力ストリームが中身を列挙してしまい、要素数 0 なら呼び出し元で `$null` に、
   要素数 1 なら中身の文字列 1 個に化け、2 個以上なら `object[]` になって `.Contains` メソッド自体が
   失われた。厄介だったのは、要素数 1 のケースで文字列に化けた値がたまたま `System.String.Contains`
   （部分一致）として動作し、一部のテストだけ「たまたま」パスしてしまったこと（デバッグ時に発見）。
   T-03/T-06 で確立済みの `return , $X` パターンをここでも適用して修正した。既存の確立済みパターンの
   適用漏れであり、新しい罠というよりは「配列・列挙可能オブジェクトを返す関数は必ず単項カンマを
   使う」という既存ルールの再確認。SKILL.md gotchas 候補。

### 実装判断（仕様に明記がない点）
- **`workbook.sheets`**: `-Sheet` の絞り込みに関わらず、常にワークブック内の全シート名を報告する
  （メタデータとして「ワークブック全体の構造」を表すため）。実際にダンプされるシート（`sheets`
  トップレベル配列）だけが `-Sheet` の絞り込みを受ける。
- **`usedRange`**: `-Range` の絞り込みに関わらず、常にシート全体の `UsedRange` を報告する
  （`-Range` はあくまで `cells` の絞り込み用途であり、シートの実際の使用範囲という情報を隠さない
  ため）。`cells` 配列だけが `-Range`/`-FormulasOnly` の絞り込みを受ける。
- **`names`**: ワークブックレベルの名前定義のみを含める。シートスコープの名前は除外する（判定方法は
  上記の罠 6 を参照）。
- **`numberFormat` の取得**: T-06 の 2 段構え（一括 → 混在時のみセル単位）を再利用したが、
  T-06 の `Get-XlsRange`（日付判定にしか `NumberFormat` を使わないため `[double]` セルだけにセル単位
  読み取りを絞る）とは異なり、`Get-XlsModel` は `numberFormat` 自体を出力フィールドとして返す契約の
  ため、混在時は「`cells` に含めると決まった」各セルについて型を問わずセル単位で読む。T-06 の
  `ConvertFrom-XlsRangeToRows` 自体は変更していない（別の内部関数 `ConvertTo-XlsModelCellList` に
  独立実装）。
- **空セルの除外**: 値も数式もないセル（`Value2` が `$null` かつ数式セルでない）は `cells` に含めない
  （タスクカード指定の方針）。数式セルは `Value2` が `$null` であっても常に含める設計にしたが、
  実機では formula セルの `Value2` が `$null` になるケースは確認していない（安全側の設計判断）。
- **`-FormulasOnly` の性能特性**: `Value2`/`Formula` の一括取得自体は範囲全体に対して常に 1 回ずつ
  行う（`-FormulasOnly` でも変わらない）。`-FormulasOnly` が主に削減するのは出力サイズと、
  `NumberFormat` が混在時に発生するセル単位フォールバック呼び出しの回数（数式セルの分だけに限られる）。
- **`address` の形式**: シート名を含まない相対アドレス（例 `"A1"`、`$` なし）。列文字は COM を使わず
  `ConvertTo-XlsColumnLetter`（純粋関数）で計算し、セル単位の `Range.Address()` 呼び出しを避けた。
- **`version`/`build`**: `Application.Version`/`Application.Build` をそのまま文字列化する。

### レビュー round 1（harness/state/reviews/T-08.md）への対応（G-16）
判定: done（blocking ゼロ）。should-fix 3 件、いずれも対応した。

1. **[should-fix] `SpecialCells` の全例外を「ヒットなし」として扱っている** → 対応した。
   `Get-XlsFormulaCellKeySet` の `catch` を `catch [System.Runtime.InteropServices.COMException]` に
   限定し、`$_.Exception.HResult -eq -2146827284`（0x800A03EC、実機確認済みの「ヒットなし」の
   HRESULT）のときだけ空の `HashSet` を返すようにした。それ以外の HResult、または
   `COMException` でない例外は `throw` で再送出する（レビューのスニペットどおり）。
2. **[should-fix] 単一要素 JSON 配列のテストがスカラー化を検出できない** → 対応した。
   `tests/Get-XlsModel.Tests.ps1` の `-AsJson` テストで、`@(...).Count` に頼っていた 6 箇所
   （`workbook.sheets` / `workbook.names` / トップレベル `sheets` / `sheets[0].tables` /
   `sheets[0].cells`）を `-is [System.Array]` の明示チェックに置き換え、レビューが追加提案した
   `workbook.links`（空配列のケース）の配列性チェックも追加した。配列性を先に固定したうえで、
   件数・中身の確認は `.Count`/インデックスアクセスで継続して行う。
3. **[should-fix] 公開関数経由のファイル不在テストがない** → 対応した。
   `tests/Get-XlsModel.Tests.ps1` に
   `'throws a next-step error and leaves no orphan Excel process when the file does not exist'`
   を追加し、`Get-XlsModel -Path <存在しないパス>` が `Invoke-XlsSession` 経由で
   `'File not found'` を含む次の一手エラーを投げ、`AfterEach` の `Assert-NoOrphanExcel` で
