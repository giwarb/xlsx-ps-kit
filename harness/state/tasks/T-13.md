## 実装メモ(Sonnet が記入)

### 方針
- `skill/reference/com-constants.md` を「計算モード・保存形式」「SpecialCells / エラー判定」
  「配置・罫線」「条件付き書式・データ検証」「グラフ」「セル挿入」「テーブル化」「財務モデルの
  色規約（Font.Color RGB 直接代入）」の節に分け、全行を「名前 / 値 / 用途 / 確認」の統一書式に揃えた。
  「確認」列は「日付（T-XX、実機。何を設定し何を読み戻して確認したか）」のテンプレートに統一し、
  未確認の空欄行を 1 つも残していない（G-12）。
- `$script:Xl`（XlsAgent.psm1）には追加していない。今回充填した定数（xlCenter/xlLeft/xlRight/
  xlContinuous/xlThin/xlEdgeBottom/xlInsideHorizontal/xlValidateList/xlCellValue/xlGreater/
  xlColumnClustered/xlLine/xlShiftDown/xlShiftToRight/xlSrcRange/xlYes）はいずれも書式・罫線・条件付き
  書式・グラフ・テーブル化の高水準操作に使うもので、モジュール本体の 8 公開関数はどれも使っていない
  （G-02: 書式・罫線・グラフ等の高水準ラッパーを追加しない、という既定方針のため）。よってモジュール
  (.psm1) は変更していない。タスクカードの「$script:Xl への追加はモジュール本体が使う定数のみ」
  という指示にも合致する。
- モジュールを変更していないため、Pester の分割回帰（A/B/C）は実行していない
  （タスクカードの完了条件どおり「変更した場合のみ」）。

### 実測方法（使い捨てスクリプト、リポジトリには残していない）
- `Invoke-XlsSession`（変更なしの既存関数）の ScriptBlock 内で、1 回の Excel セッション中に以下を
  すべて実測した（スクリプトは `%TEMP%` 配下の一時ファイルに書き、実行後・確認後に削除済み）。
  1. `Range.HorizontalAlignment` に -4108/-4131/-4152 を代入 → 読み戻して xlCenter/xlLeft/xlRight を確認。
  2. `Range.Borders.Item(9)`（下辺, xlEdgeBottom）と `Range.Borders.Item(12)`（2 行×2 列範囲の内側水平線,
     xlInsideHorizontal）を取得し、それぞれに `LineStyle = 1`（xlContinuous）・`Weight = 2`（xlThin）を
     代入・読み戻して確認。
  3. `Range.Validation.Add(3, 1, 3, 'A,B,C')` 実行後 `Validation.Type` が 3（xlValidateList）であることを確認。
  4. `Range.FormatConditions.Add(1, 5, '=3')` 実行後、生成された FormatCondition の `.Type`=1（xlCellValue）・
     `.Operator`=5（xlGreater）を確認。
  5. `Worksheet.ChartObjects().Add(...).Chart` でグラフを作成し `ChartType` に 51（xlColumnClustered）→
     4（xlLine）の順に代入・読み戻して確認。確認後 `ChartObject.Delete()` で後始末。
  6. 1 セルに値を入れて `Range.Insert(-4121)`（xlShiftDown）/`Range.Insert(-4161)`（xlShiftToRight）を実行し、
     元セルが空になり値が想定方向に 1 個ずれることを確認。
  7. `Worksheet.ListObjects.Add(1, Range, [Type]::Missing, 1, [Type]::Missing, [Type]::Missing)`
     （SourceType=1=xlSrcRange, HasHeaders=1=xlYes）でテーブル化し、`ListObject.SourceType`=1・
     `ListObject.HeaderRowRange.Value2` がヘッダー文字列と一致することを確認。
  8. 財務モデル色規約: `Range.Font.Color` に 16711680（青=RGB(0,0,255)）/0（黒）/32768（緑=RGB(0,128,0)）/
     255（赤=RGB(255,0,0)）を代入・読み戻して一致を確認。あわせて `R + G*256 + B*65536` という
     BGR Long 変換式そのものの正しさを RGB(12,34,56)=3678732 で検証した（VBA の `RGB()` に相当する
     組み込み関数は COM から呼べないため、この式を reference に明文化した）。
  - すべて `OK` で完了し、例外・想定外の値は 0 件だった。実行後 `Get-Process EXCEL` で残骸なしを確認済み。

### 踏んだ COM の罠（1 行ずつ）
- 使い捨てスクリプト内で `Hashtable` の結果を `Invoke-XlsSession` の ScriptBlock から
  `return $out`（unary comma なし）で返しても、Hashtable は他の IEnumerable（HashSet 等）と違い
  PowerShell の関数境界での自動展開（要素数 1→スカラー化、2 個以上→object[] 化）を受けないことを
  確認した（`function Test-Ht { return @{a=1} }` の戻り値の型が Hashtable のまま）。ただし今回は
  T-03/T-06/T-08 で確立済みの `return , $x` パターンに念のため合わせて記述した（実害はないが、
  他の COM コレクション（配列・HashSet 等）を返す場合は unary comma が必須なので、混同しないよう
  Hashtable は例外というより「たまたま安全」という位置づけで扱うべき、という点を記録しておく）。
- `ListObjects.Add` や `Chart` 系のように COM のオプション引数を省略したい場合は `$null` ではなく
  `[Type]::Missing` を渡す必要がある（既存パターンと同じ）。

### レビュー対応（round 1 → round 2、G-16: 指摘ごとに対応した／対応しない（理由）を記載）

1. **[blocking] xlErr\* が公知の XlCVError 値と区別されていない** → 対応した。
   `com-constants.md` の「SpecialCells / エラー判定」節を、レビューのスニペットどおり
   「Excel 名 / XlCVError 値（公式・未実測、Microsoft Learn 出典）/ Range.Value2 の実測 Int32 /
   用途 / 確認」に分離した。`$script:Xl.xlErr*` は「モジュールローカルな Value2 コード別名で
   あり XlCVError 定数値ではない」ことを明記する説明段落を追加した。XlCVError 側の値
   （xlErrNull=2000, xlErrDiv0=2007, xlErrValue=2015, xlErrRef=2023, xlErrName=2029,
   xlErrNum=2036, xlErrNA=2042）は Microsoft Learn の公式列挙定義の転記であり実測していない旨を
   各行に明記した（G-12 は「出典明記の公式値」と「実測列」の分離で担保）。
2. **[blocking] xlCalculationManual 行に確認方法がない** → 対応した。T-03 の
   `Invoke-XlsSession.Tests.ps1` で「Open/Add 後に `Application.Calculation = -4135` を設定し、
   ScriptBlock 内で同プロパティを読み戻すと -4135 のまま」であることを検証している事実に基づき、
   統一書式（何を設定し何を読み戻したか）に沿って確認欄を書き直した。新規の COM 実測は行っていない
   （既存テストで既に確認済みの内容を記録欄に反映しただけ）。
3. **[blocking] Font.Color の「常にスカラー」が実測範囲を超えた一般化** → 対応した（追加実測あり）。
   記述を「今回確認した単一セル、および全セルが同一色の範囲では」に限定した上で、混在色範囲での
   挙動を追加実測した: 2 セル範囲の各セルに異なる `Font.Color`（255 / 16711680）を設定してから
   範囲まとめて `Font.Color` を読むと `System.DBNull` が返ることを実機で確認し（同一色範囲では
   `System.Double` のスカラーが返ることも対照区として確認）、com-constants.md に追記した。
   使い捨てスクリプトで `Invoke-XlsSession` 内・フォアグラウンドで実行、確認後に温存せず削除した。
4. **[should-fix] Range.Insert は xlShiftToRight に統一** → 対応した。
   `com-constants.md` の該当行の名前を `xlToRight` → `xlShiftToRight` に修正し、値 `-4161` と
   実測記録はそのまま維持した。本タスクカードの「方針」「実測方法」節の表記もあわせて修正した。
5. **[nit] 確認欄の括弧・コード表記の不統一** → 対応した。
   `com-constants.md` の xlColumnClustered 行の確認欄を、レビュー修正案どおり全角括弧で閉じ、
   `ChartObject.Delete()` をコード表記（バッククォート）に統一した。

以上、round 1 の blocking 3 件・should-fix 1 件・nit 1 件すべてに対応した。追加実測（Font.Color
混在色範囲）は `Invoke-XlsSession` の ScriptBlock 内・フォアグラウンドで実行し、実行後
`Get-Process EXCEL` で残骸なしを確認済み。モジュール (.psm1) は今回も変更していないため、
Pester の分割回帰は引き続き対象外。
