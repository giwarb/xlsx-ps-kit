## 指摘

### [blocking] 新規マーカー名の検出だけでは、この実行の所有権確立を証明できない

- 場所: `skill/scripts/Test-XlsFormulas.ps1:176, 179-253`、`skill/scripts/XlsAgent.psm1:389-394, 3412-3432`
- 内容: CLI は事前に存在したファイル名を記録し、その後に現れた任意の `*.marker` を所有権確立の合図にしています。マーカーの PID・開始時刻を読まず、この CLI の Runspace が作ったものとも相関させていません。そのため、並行する別の XlsAgent セッションが新しいマーカーを作るとタイマーが早期に開始され、自身のマーカー確立前に TerminateProcess されて、round 1 と同じ回収不能孤児を残し得ます。
- 内容: また、Invoke-XlsSession は `FileMode.Create` でファイルを可視化した後に内容を書いて Flush します。CLI は存在した時点で確立済みと判断するため、現在許可されている `timeoutSec=0` では空または不完全なマーカーのまま強制終了する競合があります。Clear-XlsOrphans は開始時刻のない生存 EXCEL.EXE を `Skipped-UnverifiedLegacy` として停止せず、回収不能になります。
- 内容: 反対に、PID 再利用により自身のマーカー名が事前一覧に含まれていた場合は確立を検出できず、timeoutSec が開始されません。したがって、前回 blocking の「正確な PID・開始時刻・マーカーリース確立後に開始」は未達です。
- 修正案: ディレクトリ全体のファイル名差分ではなく、実行ごとの nonce を親からワーカーへ渡し、マーカー内容の書き込みと Flush が完了した後に、その nonce・PID・開始時刻を含む ready イベントを返してください。親はその完全な組を検証してからタイマーを開始します。最低値を 1 秒に制限するだけでは並行セッションとの誤認は解消しません。

```text
parent:
  runToken を生成して worker へ渡す
  exact ready(runToken, markerPath, PID, StartTicks) を待つ
  マーカー内容・生存 EXCEL.EXE・開始時刻を検証
  検証成功後だけ timeoutSec を開始

worker / Invoke-XlsSession:
  marker を排他作成
  PID・StartTicks・runToken を書く
  Flush
  ready を通知
```

テストには「自身のマーカーより先に無関係な新規マーカーが現れるケース」と「マーカー作成から内容 Flush までを遅延させるケース」を追加し、前者でタイマーが開始されず、後者で不完全なマーカーを残して強制終了しないことを固定してください。

### [should-fix] TerminateProcess が timeout 以外の最外周 catch でも使われている

- 場所: `skill/scripts/Test-XlsFormulas.ps1:315-320`
- 内容: コメントと対応記録は TerminateProcess を timeout 専用としていますが、Runspace 生成失敗などの最外周例外でも `-HardExit` を指定しています。非 timeout 経路は内側の finally が PowerShell/Runspace を Dispose/Close してから到達するため、通常の `exit 1` で十分です。
- 修正案:

```powershell
catch {
    Complete-XlsCli -Code 1 `
        -JsonText (ConvertTo-XlsCliErrorJson -Message $_.Exception.Message)
}
```

### [should-fix] Clear-XlsOrphans のテストがマーカー回収を検証し切れていない

- 場所: `tests/TestXlsFormulasCli.Tests.ps1:368-390, 430-440`
- 内容: フェイクテストは `Clear-XlsOrphans` が例外を投げないことしか検証せず、対象マーカーの削除や `Skipped-DeadPid` を確認していません。実 Excel テストも追加 PID が既に消えている場合は Clear-XlsOrphans を一度も呼ばないため、タイムアウトマーカーだけが残るケースを見逃します。
- 修正案: テスト前のマーカー集合も記録し、タイムアウト後は Excel PID の有無にかかわらず Clear-XlsOrphans を最低 1 回呼んでください。戻り値の Action と、新規マーカーおよび追加 EXCEL.EXE が最終的にゼロであることを両方検証します。
