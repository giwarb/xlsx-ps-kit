## 指摘

### [blocking] マーカーは所有権を示しても「孤児」であることを示さない

- 場所: `skill/scripts/XlsAgent.psm1:740`、`skill/scripts/XlsAgent.psm1:823`、`tests/Clear-XlsOrphans.Tests.ps1:301`、`harness/state/tasks/T-05.md:123`
- 内容: マーカーは正常な `Invoke-XlsSession` の ScriptBlock 実行中にも存在します。その間はPID・プロセス名・開始時刻のすべてが一致するため、現実装はその正常セッションを停止対象にします。`-WhatIf` テスト自身が、正常に進行中のセッションに対して `WhatIf-WouldStop` になることを実証しています。`-WhatIf` を外せば、未保存の処理中ワークブックを含む正常セッションを `Stop-Process -Force` で終了し得ます。「後始末に失敗したEXCEL.EXEだけを回収する」という関数契約およびG-10の安全保証に反するため、実装メモに運用制約として記録するだけでは足りず blocking です。マーカー書き込み側の更新はT-05で明示的に許可されているため、G-14を理由にスコープ外とはできません。
- 修正案: `Invoke-XlsSession` がセッション中ずっと保持するOSレベルのリースを導入してください。例えばPID・Ticksを同じ `FileStream` で書き、そのストリームを `FileShare.None` のままfinallyまで保持します。`Clear-XlsOrphans` はマーカーの排他オープンに成功した場合だけ孤児候補として処理し、共有違反なら `Skipped-ActiveSession` として停止も削除もしません。PowerShellホストがクラッシュすればOSがハンドルを解放し、マーカーだけが残るため回収可能になります。

```powershell
# Invoke-XlsSession: PID/Ticksを書いた同じハンドルをセッション終了まで保持する
$markerLease = [IO.File]::Open(
    $markerPath,
    [IO.FileMode]::Create,
    [IO.FileAccess]::ReadWrite,
    [IO.FileShare]::None
)
# StreamWriter等でPID/Ticksを書き、$markerLeaseはfinallyまでDisposeしない

# Clear-XlsOrphans: 読み取り・判定より先にリースを確認する
try {
    $orphanLease = [IO.File]::Open(
        $markerPath,
        [IO.FileMode]::Open,
        [IO.FileAccess]::ReadWrite,
        [IO.FileShare]::None
    )
}
catch [IO.IOException] {
    $results += [PSCustomObject]@{
        Pid = $markerPid
        MarkerPath = $markerPath
        Action = 'Skipped-ActiveSession'
    }
    continue
}

try {
    # PID・EXCEL・開始時刻の照合と停止
}
finally {
    $orphanLease.Dispose()
}
```

正常なバックグラウンドセッションに対して `Clear-XlsOrphans` を `-WhatIf` なしで呼び、プロセスとマーカーが残り `Skipped-ActiveSession` になるテストも追加してください。

### [blocking] 照合したProcessとは別にPIDを再解決して停止している

- 場所: `skill/scripts/XlsAgent.psm1:809`、`skill/scripts/XlsAgent.psm1:823`、`skill/scripts/XlsAgent.psm1:839`
- 内容: PID・名前・開始時刻を `$process` で照合した後、停止時は `Stop-Process -Id $markerPid` でPIDを再解決しています。照合後に対象が終了してPIDが再利用されると、新しく同じPIDになったユーザーのプロセスを停止し得ます。特に `-Confirm` を付けた場合は、照合からユーザー回答まで競合時間を任意に長くできます。これはfail closedになっておらずG-10違反です。
- 修正案: `ShouldProcess` の後でも同じ `Process` オブジェクトを再検証し、`Stop-Process -InputObject $process` でそのオブジェクトを停止してください。終了確認もPIDの再検索ではなく `WaitForExit` を使用します。再検証中の例外は停止しない側へ倒してください。

```powershell
if (-not $PSCmdlet.ShouldProcess("EXCEL.EXE (PID $markerPid)", 'Stop-Process')) {
    # WhatIf結果
    continue
}

try {
    $process.Refresh()
    if ($process.HasExited -or
        $process.ProcessName -ne 'EXCEL' -or
        $process.StartTime.ToUniversalTime().Ticks -ne $recordedStartTicks) {
        # 所有権を再確認できないため停止しない
        continue
    }

    Stop-Process -InputObject $process -Force -ErrorAction Stop
    if (-not $process.WaitForExit(5000)) {
        throw "Owned EXCEL.EXE PID $markerPid did not terminate within 5 seconds."
    }
}
catch {
    throw "Owned EXCEL.EXE PID $markerPid was not stopped safely: $($_.Exception.Message)"
}
```

### [should-fix] 旧1行マーカーは安全だが完全な後方互換ではなく、直接テストもない

- 場所: `skill/scripts/XlsAgent.psm1:768`、`harness/state/tasks/T-05.md:68`、`tests/Clear-XlsOrphans.Tests.ps1:198`
- 内容: 2行目がない旧マーカーを `Skipped-Unverified` に倒してプロセスを停止しない判断は、G-10上は正しいため blocking ではありません。ただし、旧バージョンが残した生きた孤児は回収されず、さらにマーカーも削除されて以後の回収証跡を失います。「後方互換上の問題はない」ではなく「安全側に機能劣化する」が正確です。また、既存テストはいずれも2行マーカーを作っており、記載された旧書式分岐を直接検証していません。
- 修正案: 生きたEXCELを指す旧マーカーは停止せず、`Skipped-UnverifiedLegacy` 等でマーカーを残すことを推奨します。少なくとも、旧1行形式について死亡PID、非Excel、生きたExcelの各結果をテストし、実装メモに回収不能という制約を明記してください。

### [should-fix] マーカー削除失敗を成功として報告する

- 場所: `skill/scripts/XlsAgent.psm1:795`、`skill/scripts/XlsAgent.psm1:811`、`skill/scripts/XlsAgent.psm1:826`、`skill/scripts/XlsAgent.psm1:849`
- 内容: すべての `Remove-Item` が `-ErrorAction SilentlyContinue` で、削除後の存在確認もありません。アクセス拒否や共有違反でも `Skipped-*` / `Stopped` を返すため、「掃除したマーカーの一覧」という戻り値契約と実態が食い違います。
- 修正案: 「既に他プロセスが削除した」は成功扱いにしつつ、削除後も存在する場合は説明付きでthrowするか、`Failed-MarkerCleanup` を返してください。

```powershell
Remove-Item -LiteralPath $markerPath -Force -ErrorAction SilentlyContinue
if (Test-Path -LiteralPath $markerPath) {
    throw "Marker '$markerPath' could not be removed. Check file permissions or an active marker lease."
}
```

## 良かった点（1〜2行、次のタスクでも続けてほしいこと）

PID解析→存在→EXCEL名→開始時刻という照合順と、開始時刻欠落・不一致を停止しない側へ倒す判断は適切です。実Excelと一致マーカーを使った `-WhatIf` テストも「停止対象判定」の陽性分岐を安全に確認する方法として妥当ですが、実際の停止・削除経路の検証にはならず、また正常セッションまで陽性になる問題は上記blockingとして解消が必要です。
