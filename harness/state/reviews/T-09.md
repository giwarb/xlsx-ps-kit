## 指摘

### [should-fix] 「厳密な逆関数」が成立する範囲とDate1904往復テストが不足

- 場所: `skill/scripts/XlsAgent.psm1:1703`、`skill/scripts/XlsAgent.psm1:2221`、`tests/Set-XlsRange.Tests.ps1:111`
- 内容: Date1904 の `-1462`、serial 60 の特別処理、1900-01-01〜02-28 に対応する OADate `[2,61)` の `-1` は、秒単位かつ正準なシリアル値について Get 側と正しく対称である。一方、Get は `yyyy-MM-ddTHH:mm:ss` までしか出力しないため、サブ秒を含むシリアル値は必ず丸められ、数学的な意味で全 `[double]` の厳密な逆関数にはならない。また負の小数 OADate は同じ DateTime に正負2通りの表現があり、例えば `-0.5` は ISO 化後に `+0.5` へ正準化され得る。現テスト名の “arbitrary serials” はこの制約を表していない。さらに Date1904 の統合テストは生 Value2 の確認だけで、タスクカードが求める公開 `Set→Get` 往復を検証していない。
- 修正案: 対称性の保証範囲を「Get が表現できる秒単位・正準 OADate」に明記してテスト名を修正し、Date1904 ブックで複数の ISO 日付／日時を `Set-XlsRange` から `Get-XlsRange` まで往復する統合テストを追加する。全 double の厳密往復を要求するなら、Get 側の小数秒出力を含む別タスクの設計変更が必要。

```powershell
$wb.Date1904 = $true
$ws.Range('A1:A3').NumberFormat = 'yyyy-mm-dd hh:mm:ss'
$expected = @('1904-01-01', '1904-02-29', '2024-01-02T12:34:56')

Set-XlsRange -Worksheet $ws -Range 'A1' -Data @(
    @($expected[0]),
    @($expected[1]),
    @($expected[2])
)
$actual = Get-XlsRange -Worksheet $ws -Range 'A1:A3'
```

### [should-fix] 架空日の不正な時刻だけ未処理例外になる

- 場所: `skill/scripts/XlsAgent.psm1:2202`
- 内容: `1900-02-29T25:00:00` は ISO 形状の正規表現に一致して架空日分岐へ入り、`TimeSpan.ParseExact` が捕捉されず例外を投げる。通常日付の `2024-02-30` は `$null` を返して元文字列を書き込むため、実装メモで宣言した「形状は合うが無効な日時は文字列のまま」という挙動と不整合。
- 修正案: 架空日の時刻解析も `try/catch` または `TryParseExact` で囲み、失敗時は `$null` を返す。`ConvertTo-XlsWriteCellValue` 経由で元文字列が維持されるテストも追加する。

```powershell
try {
    $ts = [TimeSpan]::ParseExact(
        $Matches['time'],
        'hh\:mm\:ss',
        [Globalization.CultureInfo]::InvariantCulture
    )
}
catch {
    return $null
}
```

### [should-fix] 不正JSONフィクスチャの文字コードが暗黙

- 場所: `tests/Set-XlsRange.Tests.ps1:392`
- 内容: `[IO.File]::WriteAllText($badPath, 'not valid json {{{')` がエンコーディングを指定しておらず、S-01／P-3 の「ファイル I/O は UTF-8 明示」に一致しない。内容がASCIIだけなので現在のテスト結果には影響しにくいが、規約上は明示すべき。
- 修正案:

```powershell
[IO.File]::WriteAllText(
    $badPath,
    'not valid json {{{',
    [Text.Encoding]::UTF8
)
```

G-08 は徹底されており、セル値の正規化ループは純粋な配列構築だけ、COM 書き込みは単一 `[object[,]]` の1回代入だけになっている。CSV の空欄／真偽値／doubleという最小推論も、型情報を失う文字列の曖昧さを明記したうえで Get 側の出力と整合している。

## SKILL.md gotchas 候補（実装メモに書かれていないが気づいた罠があれば）

- `yyyy-MM-ddTHH:mm:ss` への変換はサブ秒を失うため、ISO 化とシリアル化は全 double 上の厳密な全単射ではない。
- OADate の負の小数表現は同一 DateTime に正負2通りの値が対応し得るため、Get→Set で正準化される場合がある。
