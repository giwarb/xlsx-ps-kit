## 指摘

### [blocking] マーカー作成前のタイムアウトで安全に回収不能な EXCEL.EXE が残る

- 場所: `skill/scripts/Test-XlsFormulas.ps1:184-192, 225-243`、`skill/scripts/XlsAgent.psm1:380-390`
- 内容: タイマーは `Start-XlsApplication` より前から検証全体を対象にする一方、所有 PID と排他リースのマーカーは `Start-XlsApplication` が戻った後にしか作成されない。この間に TerminateProcess すると、起動済みだがマーカーのない EXCEL.EXE が残り得る。`Clear-XlsOrphans` は G-10 によりそのプロセスへ触れないため、「呼び出し元の責務」としても安全な回収手段が存在しない。受け入れ条件の「残らない、または回収手段が機能する」を満たさず、EXCEL.EXE 残留に該当する。
- 修正案: `timeoutSec` を設計どおり CalculateFullRebuild の段階に限定し、正確な PID・開始時刻・マーカーリースが確立したことを所有権ハンドシェイクで確認してからタイマーを開始する。即時終了が必要なら、JSON を返す親 CLI と STA/COM を持つ子ワーカーを分離する。親は所有権確立後にだけワーカーを停止し、リース解放後に `Clear-XlsOrphans` で回収してから timeout JSON を返す。少なくとも所有権確立前にホストを強制終了してはならない。

```text
parent CLI
  ├─ STA worker 起動
  ├─ worker から「marker ready: PID + StartTicks」を受信
  ├─ CalculateFullRebuild の timeout を開始
  └─ timeout:
       worker のみ終了
       Clear-XlsOrphans で marker-backed PID を回収
       {"error":"timeout"} / exit 1
```

### [blocking] ベースライン差分だけで Excel を直接停止している

- 場所: `tests/TestXlsFormulasCli.Tests.ps1:216-223`
- 内容: 「テスト前に存在しなかった PID」は、テストが起動した Excel だとは証明できない。180 秒の待機中にユーザーや別プロセスが起動した Excel も `$extra` に入り、直接 `Stop-Process -Id` される。これは G-10 違反であり、`XlsAgent.psm1:79-81` に記録済みの「PID 前後差分では所有権を判定できない」という過去の blocking を再導入している。PID 再利用に対する開始時刻の再検証もない。
- 修正案: 直接停止を削除し、所有権を PID・開始時刻・排他マーカーで検証する `Clear-XlsOrphans` だけを使用する。未追跡 PID が残った場合はテストを失敗させ、上記 CLI のライフサイクル不具合を隠さない。

```powershell
while ($extra.Count -gt 0 -and (Get-Date) -lt $deadline) {
    Clear-XlsOrphans | Out-Null
    Start-Sleep -Seconds 3
    $currentPids = Get-ExcelPids
    $extra = @($currentPids | Where-Object {
        $script:BaselinePids -notcontains $_
    })
}

$extra.Count | Should Be 0
```

### [should-fix] 正常終了まで TerminateProcess を使う必要はない

- 場所: `skill/scripts/Test-XlsFormulas.ps1:44-46, 85-120, 249`
- 内容: success/errors_found/refused/通常の error では EndInvoke と Runspace の Dispose/Close が完了しており、ブロック中のスレッドはない。この経路まで TerminateProcess にすると CLR・PowerShell の通常終了処理を常に破棄する。CLI を誤って既存ホスト内から実行した場合は、その PowerShell ホスト全体を即時終了する。TerminateProcess の対象が GetCurrentProcess のみで、Excel の全殺しになっていない点は正しい。
- 修正案: 強制終了は、所有権問題を解決した後の timeout 専用に限定する。通常系は `exit $Code` で終了する。

```powershell
function Complete-XlsCli {
    param(
        [int]$Code,
        [string]$JsonText,
        [switch]$HardExit
    )

    [Console]::Out.WriteLine($JsonText)
    [Console]::Out.Flush()

    if ($HardExit) {
        $handle = [XlsAgentCli.NativeMethods]::GetCurrentProcess()
        if ([XlsAgentCli.NativeMethods]::TerminateProcess($handle, [uint32]$Code)) {
            return
        }
    }

    exit $Code
}
```

### [should-fix] Start-Process の引数配列はスペース入りパスを保護しない

- 場所: `tests/TestXlsFormulasCli.Tests.ps1:53-55, 67-71`
- 内容: Windows PowerShell 5.1 の `Start-Process -ArgumentList` は配列要素を空白で連結して渡すため、「各要素が個別の引数として渡るのでクォート不要」というコメントは誤り。リポジトリまたは workbook のパスに空白がある環境ではテストヘルパーが引数を分割する。
- 修正案: Windows のファイル名には `"` を含められないため、少なくとも `$cliPath` と workbook パスを明示的に二重引用符で囲む。スペースを含む一時ディレクトリを使う受け入れテストも追加する。

```powershell
$quotedCliPath = '"{0}"' -f $cliPath
$quotedArguments = @($Arguments | ForEach-Object {
    if ($_ -match '\s') { '"{0}"' -f $_ } else { $_ }
})
$allArgs = @(
    '-NoProfile', '-NonInteractive', '-ExecutionPolicy', 'Bypass',
    '-File', $quotedCliPath
) + $quotedArguments
```

### [should-fix] タイムアウトテストが実行環境の遅さに依存している

- 場所: `tests/TestXlsFormulasCli.Tests.ps1:180-196`
- 内容: 数式 1 個の workbook が「必ず 1 秒を超える」という前提は、より高速または状態のよい環境では成立しない。また実装メモどおり、現在のテストは CalculateFullRebuild ではなく COM アクティブ化でタイムアウトしている可能性が高い。タイムアウト制御の決定的な検証になっていない。
- 修正案: タスクカードで許可されている単体代替を使い、テスト用の一時モジュールで `Test-XlsFormulas` を確実に 2 秒以上待機させ、1 秒で timeout になることを検証する。実 Excel のテストは、blocking 修正後に「マーカー確立後の計算段階」で遅延させ、`Clear-XlsOrphans` だけで回収できることを別途検証する。Excel 起動失敗から error JSON/exit 1 への変換も追加すると契約が一通り固定される。
