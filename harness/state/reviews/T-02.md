## 指摘

### [blocking] PID 差分は「自分が起動したプロセス」の証明にならない

- 場所: `skill/scripts/XlsAgent.psm1:47`、`skill/scripts/XlsAgent.psm1:61`、`skill/scripts/XlsAgent.psm1:137`
- 内容: 起動前後の PID 差分が複数なら `$diff[0]` を選んでいます。同じ時間帯にユーザーが Excel を起動した場合、その PID を `XlsAgentProcessId` として誤記録し、5 秒後に `Stop-Process -Force` でユーザーの Excel を強制終了し得ます。コード自身も同時起動時の誤検出を認識しています。単一 PID に限定すること自体は G-10 に反しませんが、その PID が自プロセスであることを確実に証明できていないため、現実装は G-10 違反です。PID 再利用に対する防御もありません。
- 修正案: `Application.Hwnd` を `GetWindowThreadProcessId` で PID に変換し、さらにプロセス開始時刻を記録してください。強制終了直前に PID と開始時刻の両方が一致しなければ fail closed とし、強制終了しないようにします。

```powershell
if (-not ('XlsAgent.NativeMethods' -as [type])) {
    Add-Type -Namespace XlsAgent -Name NativeMethods -MemberDefinition @'
[System.Runtime.InteropServices.DllImport("user32.dll")]
public static extern uint GetWindowThreadProcessId(
    System.IntPtr hWnd,
    out uint processId
);
'@
}

[uint32]$newPid = 0
[void][XlsAgent.NativeMethods]::GetWindowThreadProcessId(
    [IntPtr]$app.Hwnd,
    [ref]$newPid
)

$process = Get-Process -Id $newPid -ErrorAction Stop
if ($process.ProcessName -ne 'EXCEL') {
    throw "Excel process identity could not be verified."
}

$app | Add-Member XlsAgentProcessId ([int]$newPid) -Force
$app | Add-Member XlsAgentProcessStartTicks `
    $process.StartTime.ToUniversalTime().Ticks -Force

# 強制終了直前
$target = Get-Process -Id $targetPid -ErrorAction SilentlyContinue
if ($target -and
    $target.StartTime.ToUniversalTime().Ticks -eq $targetStartTicks) {
    Stop-Process -InputObject $target -Force -ErrorAction Stop
}
```

### [should-fix] 起動・終了途中の例外で COM の解放処理を飛ばす

- 場所: `skill/scripts/XlsAgent.psm1:50`、`skill/scripts/XlsAgent.psm1:112`
- 内容: Excel 作成後、初期プロパティ設定や PID 特定で例外になると `Start-XlsApplication` は COM オブジェクトを返せず、呼び出し側は後始末できません。また `Quit()` が例外になると `ReleaseComObject` と GC×2 が実行されません。現在の異常系テストは「起動が正常完了した後の呼び出し側例外」しか扱わないため、この経路を検出できません。
- 修正案:

```powershell
# Start-XlsApplication
$app = $null
try {
    $app = New-Object -ComObject Excel.Application
    # 初期状態設定と所有 PID の特定
    return $app
}
catch {
    if ($null -ne $app) {
        try { $app.Quit() } catch {}
        if ([Runtime.InteropServices.Marshal]::IsComObject($app)) {
            [void][Runtime.InteropServices.Marshal]::ReleaseComObject($app)
        }
        [GC]::Collect()
        [GC]::WaitForPendingFinalizers()
        [GC]::Collect()
        [GC]::WaitForPendingFinalizers()
    }
    throw "Excel initialization failed and cleanup was attempted: $($_.Exception.Message)"
}

# Stop-XlsApplication
try {
    $Application.Quit()
}
finally {
    if ([Runtime.InteropServices.Marshal]::IsComObject($Application)) {
        [void][Runtime.InteropServices.Marshal]::ReleaseComObject($Application)
    }
    [GC]::Collect()
    [GC]::WaitForPendingFinalizers()
    [GC]::Collect()
    [GC]::WaitForPendingFinalizers()
}
```

### [should-fix] 強制終了の失敗を成功扱いして返す

- 場所: `skill/scripts/XlsAgent.psm1:137`
- 内容: `Stop-Process -Force -ErrorAction SilentlyContinue` の後に消滅確認がなく、アクセス拒否などでも正常終了したように返ります。テスト側は最終的に残骸を検出できますが、ヘルパー利用側には失敗理由が伝わりません。
- 修正案:

```powershell
Stop-Process -Id $targetPid -Force -ErrorAction Stop

$deadline = (Get-Date).AddSeconds(5)
while ((Get-Date) -lt $deadline -and
       (Get-Process -Id $targetPid -ErrorAction SilentlyContinue)) {
    Start-Sleep -Milliseconds 100
}

if (Get-Process -Id $targetPid -ErrorAction SilentlyContinue) {
    throw "Owned Excel process PID $targetPid did not terminate."
}
```
