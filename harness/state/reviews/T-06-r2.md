## 指摘

### [blocking] 条件付き数値書式で適用セクションを誤る

- 場所: `skill/scripts/XlsAgent.psm1:749`
- 内容: `Select-XlsNumberFormatSection` はセクションを正数・負数・ゼロだけで選んでいる。しかし Excel では `[<100]` などの条件により、既定の正数・負数・ゼロ対応を置き換えられる。[Microsoft Learn の仕様](https://learn.microsoft.com/en-us/troubleshoot/microsoft-365-apps/excel/format-cells-settings)にも条件付きセクションが明記されている。例えば `[<100]0.00;[>=100]yyyy-mm-dd` と値 `45000` では Excel は第 2 の日付セクションを適用するが、現実装は正数なので第 1 セクションを選び、生値 `45000` を返す。逆の書式では通常数値を日付へ誤変換する。これは §3.5 の日付変換契約への逸脱。
- 修正案: 各数値セクション先頭の条件トークンを解析・評価し、条件付きセクションがある場合は最初に一致する条件または無条件のフォールバックを選ぶ。条件がない場合だけ現在の符号規則を使う。最低限、次を追加する。

```powershell
(& $script:ModuleRef {
    Test-XlsIsDateNumberFormat `
        -NumberFormat '[<100]0.00;[>=100]yyyy-mm-dd' `
        -Value 45000
}) | Should Be $true

(& $script:ModuleRef {
    Test-XlsIsDateNumberFormat `
        -NumberFormat '[<100]yyyy-mm-dd;[>=100]0.00' `
        -Value 45000
}) | Should Be $false
```

### [should-fix] Invoke-XlsSession の追加テストがストリーム契約を観測していない

- 場所: `tests/Invoke-XlsSession.Tests.ps1:170`
- 内容: `.NOTES` への契約明文化は完了しているが、追加テストはいずれも結果を `$result = Invoke-XlsSession ...` で受けている。PowerShell の代入は複数のパイプライン出力を配列にまとめるため、旧実装が `1; 2; 3` を 3 オブジェクトとして出力しても `$result` は同じ `object[]` になる。単一要素テストもスカラーの `.Count` と `[0]` で通り得るため、「呼び出し元のパイプには 1 オブジェクトだけ流す」という契約を固定できていない。
- 修正案: 代入前のパイプラインを `ForEach-Object` で直接観測し、観測数が 1、かつその 1 要素が配列であることを検証する。

```powershell
$observed = New-Object System.Collections.ArrayList

Invoke-XlsSession -Path $path -ScriptBlock {
    param($app, $wb)
    1
    2
    3
} | ForEach-Object {
    [void]$observed.Add($_)
}

$observed.Count | Should Be 1
($observed[0] -is [array]) | Should Be $true
$observed[0].Count | Should Be 3
```

## SKILL.md gotchas 候補（実装メモに書かれていないが気づいた罠があれば）

- 条件付きカスタム書式では、セクションは正数・負数・ゼロではなく `[条件]` で選ばれる。条件トークンは日付判定から除外するだけでなく、適用セクションの選択に使う必要がある。
- PowerShell では変数代入後の配列形状だけでは、複数出力ストリームと非列挙の単一配列を区別できない。ストリーム契約のテストは代入前のパイプラインで出力個数を観測する。
