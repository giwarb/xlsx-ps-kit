## 指摘

### [blocking] StartTicks を解析するだけで実プロセスと照合していない

- 場所: `skill/scripts/Test-XlsFormulas.ps1:234-258`、`tests/TestXlsFormulasCli.Tests.ps1:238-242,453-493`
- 内容: runToken は実行ごとに `Guid.NewGuid()` で生成され、完全一致する ready パスだけを読むため、別セッションとの混同は解消されている。また、Invoke-XlsSession は実マーカーの Write+Flush 後に ready を書くため、マーカー可視化との競合窓も閉じている。
- 内容: 一方、ready の StartTicks は `TryParse` するだけで、`Get-Process` が返したプロセスの `StartTime.ToUniversalTime().Ticks` と比較していない。現在は同じ PIDのプロセスが何か生存していれば、StartTicks が `0` や別プロセスの値でも所有権確立と判定する。返却した `StartTicks` も以後使われないため、前回要求した PID/StartTicks/token の完全一致と PID 再利用耐性は未達。
- 内容: 追加テストも常に正しい StartTicks を書くため、この欠落を検出できない。強制終了前の正確な所有権確立がまだ証明されず、前回 blocking は完全には解消していない。
- 修正案:

```powershell
[long]$readyStartTicks = 0
if (-not [long]::TryParse($lines[1], [ref]$readyStartTicks) -or
    $readyStartTicks -le 0) {
    return $null
}

$proc = Get-Process -Id $readyPid -ErrorAction SilentlyContinue
if (-not $proc) {
    return $null
}

try {
    $proc.Refresh()
    if ($proc.HasExited -or
        $proc.StartTime.ToUniversalTime().Ticks -ne $readyStartTicks) {
        return $null
    }
}
catch {
    return $null
}
```

テストには、正しい runToken と生存 PIDを使う一方で最初は誤った StartTicks の ready を書き、3 秒後に正しい値へ置き換えるケースを追加する。現行コードなら約 1 秒、修正後なら約 4 秒で timeout になるため、PID 再利用相当の誤認を決定的に検出できる。

### [should-fix] Clear-XlsOrphans の Action は収集するだけで検証されていない

- 場所: `tests/TestXlsFormulasCli.Tests.ps1:543-574`
- 内容: Excel PID の有無にかかわらず Clear-XlsOrphans を最低 1 回呼び、新規マーカーと追加 EXCEL.EXE が最終的にゼロであることは確認するようになった。この部分は改善している。
- 内容: ただし `$clearResultsSeen` は追加されるだけで一度も参照されず、コメントと対応記録が主張する戻り値の `Action` 検証は実装されていない。前回 should-fix のうち Action に関する部分は未解消。
- 修正案: フェイクモジュールにも自 PID・StartTicks を含む排他マーカーを持たせる。CLI が TerminateProcess された後に Clear-XlsOrphans を呼び、対象 PID の結果が `Skipped-DeadPid`、かつ対象マーカーが削除されたことを明示的に検証する。実 Excel テストでは、新規マーカーに対応する結果が得られた場合に `Stopped` または安全側の Action であることも確認する。

### [nit] timeout ごとに ready ファイルが残る

- 場所: `skill/scripts/Test-XlsFormulas.ps1:408-414,423-425`
- 内容: `$timedOut` の場合だけ ready ファイルを削除しないため、実行ごとに一意な `.ready` が TEMP に蓄積する。Clear-XlsOrphans は参照しないため安全性への影響はないが、テストを含め timeout のたびに残骸が増える。
- 修正案: ready は所有権確認後には不要であり、内側の finally は HardExit 前に実行されるため、timeout 時もベストエフォートで削除する。
