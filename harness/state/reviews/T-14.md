## 指摘

### [blocking] 単一セルへの Value2 スカラー代入が G-08 に違反

- 場所: `skill/reference/patterns.md:63`, `skill/reference/patterns.md:84`, `skill/reference/patterns.md:88`, `skill/reference/patterns.md:167`
- 内容: `$ws.Range('A1').Value2 = '...'` などのスカラー代入がある。G-08 は複数セルだけでなく、すべての `Range.Value2` 代入を `[object[,]]` に限定している。AutoFit、コメント、名前定義のスニペットがガードレール違反。
- 修正案: コメント用のセル値は不要なので代入自体を削除する。AutoFit と名前定義は 1×1 配列にする。変更したスニペットは G-12 のため再実行し、確認記録も更新する。

```powershell
$data = New-Object 'object[,]' 1,1
$data[0,0] = 'This is a fairly long piece of text for column width test'
$ws.Range('A1').Value2 = $data
```

### [should-fix] グラフ挿入スニペットが成果物のグラフを削除する

- 場所: `skill/reference/patterns.md:137`, `skill/reference/patterns.md:152`, `skill/reference/patterns.md:155`
- 内容: `ChartObjects.Add` は埋め込みグラフを作成する一方、`ChartObject.Delete()` はそのオブジェクトを削除するため、スニペット終了時にはグラフが残らない。[Microsoft Learn の Add](https://learn.microsoft.com/en-us/office/vba/api/excel.chartobjects.add)／[Delete](https://learn.microsoft.com/en-us/office/vba/api/excel.chartobject.delete) の契約とも一致する。T-13 の定数実測で必要だった後始末を、成果物編集用パターンへ持ち込んでいる。また、確認欄の `ChartType=4` は公開スニペットに含まれず、コードは 12 行で 5〜10 行要件も超える。
- 修正案: 公開スニペットから `Delete()` を除き、`Add(...).Chart` を一行にまとめて 10 行以内にする。確認は公開コードと一致させ、終了時の `ChartObjects().Count` が作成前より 1 増えたことを記録する。

```powershell
$chart = $ws.ChartObjects().Add(100, 10, 300, 200).Chart
$chart.SetSourceData($ws.Range('A1:B3'))
$chart.ChartType = 51 # xlColumnClustered
```

### [should-fix] データ検証の定数名と一次資料の説明が不整合

- 場所: `skill/reference/patterns.md:8`, `skill/reference/patterns.md:119`, `skill/reference/patterns.md:127`
- 内容: 冒頭では定数の一次資料をすべて com-constants.md としているが、`xlValidAlertStop=1` は同ファイルにない。また第 3 引数の `3` は公式には `xlEqual` だが、コメントに定数名がない。`Validation.Add` の Operator は optional なので、リスト検証で利用しない値をマジックナンバーとして渡す必要もない。[Validation.Add](https://learn.microsoft.com/en-us/office/vba/api/excel.validation.add)、[XlDVAlertStyle](https://learn.microsoft.com/en-us/office/vba/api/excel.xldvalertstyle)、[XlFormatConditionOperator](https://learn.microsoft.com/en-us/office/vba/api/excel.xlformatconditionoperator)。
- 修正案: Operator は `[Type]::Missing` にし、実測済みの `xlValidAlertStop=1` を com-constants.md に確認方法付きで追加する。変更後の呼び出しを再実行する。

```powershell
$cell.Validation.Add(3, 1, [Type]::Missing, 'A,B,C')
# Type=xlValidateList(3), AlertStyle=xlValidAlertStop(1)
```

### [should-fix] AutoFit とシート名クォートの説明を実測範囲に限定する

- 場所: `skill/reference/patterns.md:57`, `skill/reference/patterns.md:161`
- 内容: `Worksheet.Columns` が返すのも「列オブジェクト」ではなく `Range` であり、`Range.AutoFit` の対象は行または列を表す Range に限られる。現在の「範囲・列オブジェクトの両方」は任意の Range に使えるように読める。[Range.AutoFit](https://learn.microsoft.com/en-us/office/vba/api/excel.range.autofit)、[Worksheet.Columns](https://learn.microsoft.com/en-us/office/vba/api/excel.worksheet.columns)。また Names.Add の実測は `Sheet1` だけなので、単引用符で囲めば一般に安全という記述は実測を超える。シート名自身に単引用符がある場合のエスケープも扱っていない。
- 修正案: AutoFit は「行・列を表す Range に対するメソッド」と記述する。名前定義は主張を `Sheet1` の実測に限定するか、単引用符を二重化してスペース・単引用符入りシート名でも再確認する。

```powershell
$sheetName = $ws.Name.Replace("'", "''")
$refersTo = "='{0}'!`$A`$1" -f $sheetName
```
