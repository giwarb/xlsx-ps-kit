## 指摘

### [blocking] xlErr* の値が Excel の公知の定数値ではなく、Value2 のマーシャリング後コード

- 場所: `skill/reference/com-constants.md:29`
- 内容: Microsoft の [XlCVError 列挙](https://learn.microsoft.com/en-us/office/vba/api/excel.xlcverror)では、例えば `xlErrValue=2015`、`xlErrNull=2000`。現在の負数は、PowerShell COM で `Range.Value2` を読んだ際の HRESULT 形式の Int32 であり、実測値としては正しいものの、Excel 定数の名前と値の組としては異なる。現在の表はスキル利用エージェントが XlCVError 定数として流用する危険があり、記録された実測が検証した量と表のラベルが一致しないため G-12 違反。
- 修正案: 公式列挙値と PowerShell で観測した値を明確に分離する。

```markdown
| Excel 名 | XlCVError 値 | Range.Value2 の実測 Int32 | 用途 | 確認 |
|---|---:|---:|---|---|
| xlErrValue | 2015 | -2146826273 | PowerShell COM で読み取った #VALUE! の判定 | ... |
```

`$script:Xl.xlErr*` は「モジュール内のローカルな Value2 コード別名であり、Excel の XlCVError 定数値ではない」と明記する。

### [blocking] 全行に確認方法があるという G-12 記録を満たしていない

- 場所: `skill/reference/com-constants.md:14`
- 内容: `xlCalculationManual` は日付・タスク・実機という記録だけで、「何に設定し、何を読み戻したか」がない。タスクカードの完了条件と、同ファイル冒頭の統一書式に反するため、G-12 をレビュー側で確認できない。
- 修正案:

```markdown
| xlCalculationManual | -4135 | Application.Calculation | 2026-08-17（T-03、実機。Workbook を開いた後に `Application.Calculation = -4135` を設定し、同プロパティを読み戻して -4135 を確認） |
```

### [blocking] Font.Color の「常にスカラー」は実測範囲を超えた主張

- 場所: `skill/reference/com-constants.md:93`
- 内容: 実装メモに記録された実測は、単一の色を代入して同値を読み戻したもの。そこから「書き込み・読み戻しとも常に Long のスカラー」と一般化する根拠は記録されていない。公式仕様でも `Font.Color` は [read/write Variant](https://learn.microsoft.com/en-us/office/vba/api/excel.font.color) であり、複数セル・混在色を含めた「常に」は G-12 上の未確認内容になる。
- 修正案: 「今回確認した単一セル／同一色範囲では BGR Long を読み戻した」に限定する。普遍的な記述を残すなら、混在色範囲も実測し、対象範囲と戻り値型・値を記録する。

### [should-fix] Range.Insert にはメソッド固有の xlShiftToRight を使う

- 場所: `skill/reference/com-constants.md:69`
- 内容: `-4161` と右シフトの挙動は正しい。一方、`Range.Insert` の Shift 引数で公式に定義される `XlInsertShiftDirection` の名前は [xlShiftToRight](https://learn.microsoft.com/en-us/office/vba/api/excel.xlinsertshiftdirection)。`xlToRight` は同値の別列挙名で、用途欄と対応する列挙型がずれているため、エージェント向け reference として紛らわしい。
- 修正案: com-constants.md とタスクカードの `xlToRight` を `xlShiftToRight` に統一する。値 `-4161` と実測記録は維持してよい。

## 良かった点（1〜2 行、次のタスクでも続けてほしいこと）

重点値の `xlCenter=-4108`、`xlContinuous=1`、`xlThin=2`、`xlSrcRange=1`、`xlYes=1` は Microsoft の公知値と一致する。BGR 式 `R + G*256 + B*65536` と例 `RGB(12,34,56)=3678732` も、[COLORREF の 0x00bbggrr 配置](https://learn.microsoft.com/en-us/windows/win32/gdi/colorref)と一致する。用途別の節分けと、reference 専用定数を `$script:Xl` に追加しない判断も適切。

## SKILL.md gotchas 候補（実装メモに書かれていないが気づいた罠があれば）

- 数値を COM プロパティへ代入して読み戻す実測は「その数値の挙動」を確認するが、型ライブラリ上の列挙名までは確認しない。メソッド固有の列挙名との照合が別途必要。
- `Range.Value2` のエラー Int32 は XlCVError の公知の列挙値そのものではなく、COM マーシャリング後の HRESULT 形式になる。
