## 指摘

### [blocking] 全条件不一致時に偽の条件付きセクションを選ぶ

- 場所: `skill/scripts/XlsAgent.psm1:892`
- 内容: すべての数値セクションが条件付きで、どの条件にも値が一致しない場合、現在は無条件で `$Sections[0]` を返す。例えば書式 `'[<0]yyyy-mm-dd;[>100]0.00'` と値 `50` では両条件とも偽なのに、第1セクションの日付書式を選び、`50` を ISO 日付へ誤変換する。Excelでは条件を順に評価し、第3セクションがあればそれが残りの数値を扱うため、偽だった第1条件へ戻ることはない。[Microsoft の条件付き数値書式の説明](https://techcommunity.microsoft.com/blog/excelblog/conditional-number-formatting/850068)とも不一致であり、日付変換契約への逸脱。r2 の代表例と無条件 catch-all は直っているが、このフォールバックにより blocking は完全には解消していない。
- 修正案: 条件一致も無条件セクションもない場合は、第1セクションではなく `$null` または空文字列を返し、日付トークンなしとして扱う。少なくとも次の回帰テストを追加する。

```powershell
(& $script:ModuleRef {
    Test-XlsIsDateNumberFormat `
        -NumberFormat '[<0]yyyy-mm-dd;[>100]0.00' `
        -Value 50
}) | Should Be $false
```

```powershell
# Select-XlsNumberFormatSection 内
# どの条件にも一致せず、無条件の数値セクションもない。
return $null
```

## 良かった点（1〜2 行、次のタスクでも続けてほしいこと）

r2 の2つの代表的な条件付き書式は値に基づいて正しく選択され、無条件 catch-all のテストも追加されている。ストリーム契約テストは代入前の `ForEach-Object` で出力数と配列型を直接観測する形になり、前回 should-fix は解消した。
