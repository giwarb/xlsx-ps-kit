## 指摘

### [should-fix] `SpecialCells` の全例外を「ヒットなし」として扱っている

- 場所: `skill/scripts/XlsAgent.psm1:975`
- 内容: 現在の `catch` は、数式セルなし以外の COM 障害や予期しない実装エラーも空集合へ変換する。後続処理が成功すると、実際には数式があるのに `formula = $null` の不完全なモデルを正常結果として返す可能性がある。S-7 の正常系例外だけを限定して処理したい。
- 修正案:

```powershell
try {
    $formulaRange = $RangeObj.SpecialCells($script:Xl.xlCellTypeFormulas)
}
catch [System.Runtime.InteropServices.COMException] {
    if ($_.Exception.HResult -eq -2146827284) { # 0x800A03EC
        return , $keySet
    }
    throw
}
```

### [should-fix] 単一要素 JSON 配列のテストがスカラー化を検出できない

- 場所: `tests/Get-XlsModel.Tests.ps1:431`
- 内容: `@($parsed.sheets).Count` は、JSON が配列ではなく単一オブジェクトや文字列になっていても 1 を返す。PowerShell ではスカラーへの `[0]` も成功するため、後続 assertion も配列性を保証しない。実装の `.ToArray()` と `ConvertTo-Json -Depth 10` は設計上妥当だが、回帰テストがその契約を固定できていない。
- 修正案:

```powershell
($parsed.workbook.sheets -is [System.Array]) | Should Be $true
($parsed.workbook.names -is [System.Array]) | Should Be $true
($parsed.sheets -is [System.Array]) | Should Be $true
($parsed.sheets[0].tables -is [System.Array]) | Should Be $true
($parsed.sheets[0].cells -is [System.Array]) | Should Be $true
```

空の `links` についても `($parsed.workbook.links -is [System.Array])` を確認すると、全配列キーを固定できる。

### [should-fix] 公開関数経由のファイル不在テストがない

- 場所: `tests/Get-XlsModel.Tests.ps1:445`
- 内容: チェックリスト T-5 が挙げる異常系のうち、本関数に直接関係する `-ReadOnly` でのファイル不在が未検証。公開関数経由でエラー内容と Excel の後始末を確認する価値がある。
- 修正案:

```powershell
It 'throws a next-step error and leaves no Excel process when the file does not exist' {
    $path = New-TempXlsxPath
    $errorSeen = $null

    try {
        Get-XlsModel -Path $path
    }
    catch {
        $errorSeen = $_
    }

    $errorSeen | Should Not Be $null
    $errorSeen.Exception.Message | Should Match 'File not found'
}
```

`AfterEach` の `Assert-NoOrphanExcel` がプロセス残留も検証する。
